2026-11-08, isolated integration on local v0.6 source `37beae2`. Published

## What changed

- New `WorldSimulation.new(seed, profile_id = "early_v1")` / `reset(...)` and
  `BattleSimulation.reset(seed, profile_id = "early_v1")` use early100HP by default.
  Invalid reset IDs return false without changing the current state.
- Profile data retain exact immutable IDs/revisions: early_v1/1, late_v1/1 and
  legacy_test_v0/0. Future tuning must use a new ID/revision. The two gameplay
  profiles have identical100HP, speed3 and guard (1s,50% incoming damage).
  Offense, reach and finite skill target limits differ. Enemy count is not input.
- Commander authority, each canonical ticket and saved BattleSim carry
  `{id, revision}`. Actual stats are reconstructed from trusted profile data,
  then existing weapon/condition rules apply exactly once. No saved stats blob
  can replace the profile. Session identity must equal its canonical ticket.
- New campaign and training scenes use early. Explicit
  `--training-profile=late_v1` selects a **training test tier only**; campaign
  remains early. No experience/age/equipment unlock path is claimed.
  HUD labels distinguish EARLY / 100HP, LATE TEST and V0.6 LEGACY.
- No changes to controls, camera, renderer, ordinary-soldier offense/defense,
  story/cast, assets, paid resources, outcome accounting or death rules.

## Save compatibility

Transport envelope schema1 is unchanged. World6 adds required profile references;
only World5's original shapes are migrated. The migration adds legacy identity to
commander/tickets/sessions and increments the world version. It never clamps360HP
to100, refreshes cooldowns, resets guard/RNG/input, settles outcomes, heals, changes
history or rewrites files on load. Full typed, canonical and causal checks follow
on a detached candidate before the live authority adopts it.

Genuine old running, pending victory, committed victory, cancelled, dead and
life-node checkpoint files were originally generated by unmodified local
`37beae2` using actual CampaignStore writes and real combat. A second generation
matched every byte. The public-source reproduction recipe uses the tree-identical
published `e86a1ad2ecbeadfba53d59a1ed6b8cebee7f366b`, retaining original provenance
in the manifest. Actual regeneration from that public source passed and all 20
save/state/trace artifacts matched the original bytes; only manifest provenance
changed. See [public reproduction evidence](evidence/v06-public-source-reproduction.log).
All original fields compare exactly after removing only the new metadata.
A running old save also matches1,773 original-engine per-frame state hashes through
natural terminal combat and the complete post-settlement state. Initial active
legacy guard, all cooldowns, unsynced elapsed, queued events and changed RNG survive.
Fixture recipe and full expectations: [tests/fixtures/v06](../tests/fixtures/v06/README.md).

Current early/late/legacy saves retain exact guard/cooldowns, input and next-frame
state; whole-fight comparisons and separate-process recovery test every tier.
Missing/unknown/wrong-type/mismatched references and profile-exceeding HP/timers are
rejected atomically. Receipt, casualty, resource, event and clock audits remain.
No campaign can silently switch tiers in the normal UI. As before, this is not
cryptographic anti-cheat: a deliberately coherent rewrite of all save metadata
cannot be distinguished from another valid authored campaign of that tier.
