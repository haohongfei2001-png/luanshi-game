## 2. 主线执行顺序（按 Gate 产出软件，不是永久停留在某个 Gate）

- 修复现有 PR #10 的字体/CI/交互真实失败，集成前保留日志和回归。消除测试工具自己的错误，而不屏蔽 Godot 引擎错误；合法字体需记录许可证，版权不明的商用字体不能偷偷随包分发。
- 建立跨 20v20、100v100、250v250、**512v512** 的**实时接战** benchmark 场景与指标采集（模拟 CPU、渲染 GPU、骨骼、导航/避碰、输入延迟、内存、帧时间）。大型压力案例从项目早期就开始运行，不能等绘完全部美术再发现 1024 人无法渲染。

### B1 — 玩家动作、武器与视觉原型
- 制作一个有真实面部/手/服装/武器的**成熟原生 3D 可控角色母版**，攻防动画与方向/武器命中判定一致。
- 九种配置：剑、刀、棍、枪、长刀、弓、弩、剑盾、双剑；每套明确的普攻/武器技能/防御与节奏，优先做差异化强的架构与动作实现，逐项扩展，而不是 9 个图标套同一伤害盒。
- 近远镜头和真实战斗动作、远近音画、弓箭/弩弹道、移动/骑乘切换。角色初期可一敌二，后期高攻击但血条上限受控。以真实游戏操作视频/回归证明，而非渲染图。
- 不要为剧情开发对话、人物传记、结婚/后嗣等不直接帮助初版战斗的系统。

### B1.5 — 最新 Owner 性能裁量：普通士兵可以笨，但看起来和结算必须真打

**先于 B2 贯彻 `PRODUCT_DECISIONS.md §1G`**。普通小兵不是高级全自主 NPC，可采用很简单的攻击、防御、士气、武器/射程、阵营、位置与受击/逃亡的有限状态；小队/将领共享战略目标、路径与阵型，士兵局部执行。每名小兵仍拥有可追溯真实伤亡与军籍，画面中攻击动作与实际命中/血量一致。可通过附近目标网格、局部邻居缓存、分帧/低频 AI、动画相位差、远景 LOD、GPU 批处理提高吞吐，不强制每一帧为 1024 人各做复杂规划。

**性能无法达标时按顺序降成本**：① 单兵 AI/寻路复杂度；② 无关远景动画/骨骼/碰撞更新；③ 重复高价特效、阴影和不必要的独立 draw call；④ 经实测的内部渲染比例与品质选项。尽量保留画面可见 1024 人、主角操作、将领指挥、兵种/姿态、真实战损和 60 FPS 目标。**不要用静止/虚假互砍来达标**。

### B2 — 千人军队实体/兵种/性能架构
- 每军 512 人的持续士兵身份/装备/军官/队伍归属与死亡记录；步兵、枪阵、弓弩、盾兵、骑兵、战车、攻城队按实体供给。
- 实现群体指挥/局部攻击 AI、空间划分、导航/避碰、模型与动画 LOD、有效遮挡/渲染批处理；**近景真实命中/远处实体战损连续**，镜头横向移入接战区时无复活/停滞/凭空清兵。
- 真实战斗中的持续帧率优先，不搞几何体占位永远不精修。每达一个兵员量级都保存**录像 + 均值/P95/P99 帧时间 + CPU/GPU breakdown**，不能只报告“断言数增加”。

### B2.5 — 2026-11-12 新增 Owner 军事体验硬要求：敌我都有高战力将领

**用户已明确指出，之前只有“玩家强、小兵弱”的战斗是不完整的。读取 PRODUCT_DECISIONS.md §1H、BATTLE_FIRST_V1_OWNER_SPEC_20261112.md §4.3/5.1 和 ACCEPTANCE_MATRIX.md §7F-B。** 这项需求与九种武器/千人 AI/胜负系统直接相关，现有活跃千人战场 PR 必须处理，不能拖到未来长篇剧情。

- **双边层次**：每方有战场主将/副将/基层军官及可以完全不在战场的上层主帅；将领等级、武器、护卫、阵型、目标、权限、士气/能力与伤情是实际战争状态。不能默认敌方最高主帅每场都在画面中央，不能只产生普通兵和 88HP 的同质军官。
- **双方强力战斗者**：主角可有实际能力在战场中击倒几十普通兵，但敌方高级将领也能以同类武器/技能与玩家近战交锋、杀伤我军普通兵/将领；友方其他高阶将领同样能杀敌。不能把敌方强将做成需要主角亲手击杀的 Boss 终点；离镜头后继续攻杀和统军。
- **强将操作公平**：射程、起手/后摇、朝向、格挡/闪避、技能/体力/防御与弱点真实、可反制。可复用玩家九武器系统，按战术层级和武器区分，不进行全知读键或靠超高血条假装强。
- **指挥/保护/继任**：主帅可能在后方，战场由主将代理；高阶将领可被亲兵保护、击伤失能、从战场撤离或被真实救起/医治、被俘或死去。命令可能继续由副将执行，也可能延误/失控并导致局部溃散；不允许死亡者复活。
- **胜负裁决**：替换当前一些简单的“玩家死亡 Game Over / 抢院 / 72% 死伤固定结算”组合为真正目标与军事态势评估。玩家死仍本人生涯结束，**但不等于敌军自动打赢战争**。斩杀敌帅/多名将领也不是自动胜利；只有实际军队因指挥/士气/兵力/退路/地形/补给/战役目标改变而失去作战能力，才自然败退/降服。敌我主帅都活着也可以正常决出胜负。
- **实现方式**：普通小兵继续廉价 FSM；将领是数量少、可以承担更复杂 AI 的单位。建议**指挥层级状态/战场强将战斗/战役态势判定**分离模块，避免把所有敌将判断与胜负硬塞进 Godot 单个 step()。要求存档迁移兼容、动态战损与 WorldSim 保持一致。
- **验收**：在“玩家只杀小兵 / 玩家与敌将搏斗 / 敌将由友军击倒 / 敌帅在后方 / 敌帅死但部队未崩 / 敌帅死引发实际崩溃 / 双方主将未死但一方达成目标 / 主角战死但军队继续”等情境下提交真实固定种子回归、渲染证据与战役记录。正式剧情与实名角色仍由 Owner 以后创作，不要自写。

### B3.5 — 新增战场类型与军种体系（Owner §1I，必须纳入后续真实开发）

Codex 在当前可运行的千人河关战场和双方高级将领基础上，逐步做出**可复用的战争任务与地形系统**，不能停留在多写 15 个关卡名字。详规：`docs/BATTLEFIELD_VARIETY_AND_FORCE_ROLES_20261112.md`，专项 QA：`docs/ACCEPTANCE_MATRIX.md §7F-C`。

**尽快补到当前战场**：一套比普通兵强、又未必是最高将领的**叫阵小将/先锋**角色，及精锐/亲兵/斥候、盾/枪、弓弩/骑兵、工兵/运输等兵种区分；先锋可率队开路与先攻，叫阵仅制造可回应/可拒绝的战术压力，不能通过斩将自动赢。**地形/桥/高差、守点/攻门、多据点与道路后勤**是真实作战因素；玩家越强敌方强将亦会独立战斗/杀伤我方，真军力与任务决定结果。

**系统扩展**：平原正面、复杂地形正面、夜袭、包围/突围、山林/丛林、埋伏/绕道、不同城池的攻/守/夺取、截粮及水源/仓储交通、火攻、投石车/机关陷阱、河道/舟桥/水战。场景受视野、行军、交通、侦察、火势/天气、弹药与真实物资影响；维护世界状态、军令和存档。先复用一张有深度的地图和模块化任务，再形成多样化地理/城池，不制造一批无效空地图。

**技术阶段能力**：火炮/炮兵和完整海战也是 Owner 要求，但**大规模舰队、成熟炮舰和工业军制必须跟随世界技术/生产链出现**，初始唐式战场不得硬塞近代大炮。河战/舟船能较早实施，海航线/舰船/炮组系统需独立开发。标记 `NEXT_EXPANSION` 或 `ERA_GATED_FUTURE` 只是实施次序，不是从产品目标中移除。

Codex 对当前 PR #17/#18 的代码/CI/性能优先保证不倒退；本阶段只在无冲突新分支按系统交付，并保留真实战斗录像、固定种子军情对照、物资/伤亡守恒与 M5 状态说明。**剧情依然完全留给 Owner**。
