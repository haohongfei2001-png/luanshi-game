## B. 高质量美术优先，不再从粗糙几何打补丁

1. 当前 scripts/field/figures.gd 的 Builder.rod/block/loft 与 scripts/field/landscape.gd 的部分程序化建模只是技术基线，不是已获认可的正式美术底稿；已有 scripts/field/presentation.gd 的 CompanyArt.fighter / MultiMesh 是可优化的批量呈现层，不是必须维持的最终美术方法。**保持既有真实战斗/军籍/存档，重建质量不足的视觉表现**。
2. 优先利用合法、可编辑、可在 Godot 4 中真正运行的专业级模型、衣甲、武器、骨架、动画、建筑与环境底座。按照资产优先规范里的具体候选逐个核实 license、源文件可得性、Blender/FBX/glTF/GLB、拓扑/LOD、材质与动画兼容性、真实镜头品质。只选少量能服务统一风格的资产；未取得就标 NOT_ACQUIRED，**不能借用商店预览冒充导入效果**。严禁购买未经 Owner 新授权的付费资产、盗用版权内容或将受限原始模型上传公开 GitHub。
3. 尝试真正合法可用的免费/CC0/已有原创资源和已安装的 Blender/Godot 管线；没有可用付费素材也要完成独立的导入、动画与材质技术流水线，并继续制作高质量原创资源。**资产选择有阻碍，不等于整个开发停止**；但不能因此退回粗糙占位模型并宣布美术达标。
4. **优先顺序**：一个高质量普通枪兵与盾兵（含敌我阵营差异）→ 弓手和主角/敌将 → 统一骨架与动作/武器握点/受击 → 河关城门/道路/河岸/树草 → 真正可玩战斗里的近中远统一 → 九武器、精锐/骑兵/战车/攻城扩展。可在独立分支制作视觉母版，但必须尽早集成到主游戏的真实河关场景。
5. 高强度借鉴八款标杆的「可迁移质量方法」：赵云传可操作斜俯视镜头；王者荣耀的清晰造型与商业完成度；全面战争：三国的军阵；战意的兵种和接触；真三起源的动作重量；帝国时代 IV 的城池；燕云十六声的古代空间；炽焰帝国 II 的个人与军团共存。不要照抄独创角色、具体场景、模型/贴图/动作/UI，也不要把不同游戏画风机械混合。
6. 一切美术修改必须通过正式游戏内同条件对照：真实可操作**默认跟随、近、中、远**机位，普通兵和将领、城门和地形一同观察。正常速度操作、走跑、挥砍/刺击、击中、受创、阵列推进和倒地都必须可信。不能只有 Blender 单独渲染、AI 图、静态镜头、滤镜、加几个甲片或单个精致主角。

## C. 功能与性能开发不停止，但必须服务实际体验

1. 主体仍为 Godot 4，先修现实可见的高影响质量缺陷，再继续战斗玩法；不因“更先进”而随意换引擎。玩家 W/A/S/D、鼠标瞄准与技能、兵种差异、军官独立行动、真实命中/伤亡、军令、士气/战斗强迫性、追击/撤退/投降、占门/保粮等任务都保持可玩。
2. 512 对 512 普通兵 + 将领/主角是**战场容量与持续性能基线**，非每场都固定 1024 人、非要求所有人同时出现在镜头。保证部队人数/装备/俘虏/死伤守恒，近景有实际动作和命中，远景按批次可算但不能冻结屏外战事。
3. 对高质量模型设分层细节：近景真实骨架与实际受击，中景共享骨架或优化动画，远景保留可读人体和编队、合适 LOD/实例化/材质整合。不要把昂贵高模 1024 份生硬复制，也不要为帧率把所有人换回积木。
4. 每个重要改动都做真实输入回归、存档/战役后结算回归和性能 A/B；记录设备、真实窗口/内部像素、AA、LOD、人数、画质、P50/P95/P99、长帧与热稳态。真实 M5 20 分钟 512v512 **稳定 60 FPS 为基线**；90/120FPS 是后续优化目标。未获得 M5 访问权限则记录 DEVICE_NOT_RUN，不可冒充。
5. 不为凑游戏时长加入大量同质空战役或粗糙素材。**完整度＝可靠、精致、真的有乐趣且高水准地完成已决定核心能力**，不是文件 GB、提交次数或大量无人验收的新功能。

## D. 反复运行的开发闭环：一个切片未合格，不进入粗糙的大规模复制

每轮按此顺序，不需要 Owner 给下个步骤：

**侦测缺口 → 定义一个实际可玩的最小高价值切片 → 修改真实代码/资产 → 本地/托管 GUI 运行 → 原像素截图/正常速度录屏 → 测试、性能、版权与战场逻辑核对 → 对照标杆找出最明显失败 → 修复或换方法 → git commit + GitHub PR/合并（符合已有工程策略）→ 更新状态 → 自动选择下一个切片。**

- 切片应能在当前执行窗口内完成实质验证，建议一个角色/一套装备、一段动画/接触、或一个完整环境区块，避免一次性把整个游戏重写；**同一切片对目标连续改进**，而非为躲避困难跳去另一块粗糙功能。
- 实际品质达不到时，明确评分依据和具体差距（人物结构、动作、镜头、场景、材质、互相遮挡、性能等），找到**根本原因并替换不合格底层方案**。禁止输出“已经显著更高级”这种无法检验的自夸结论。
- 至少对 ARTREF-01～12 标注真实 PASS/FAIL/NOT_RUN 并关联证据。**Owner 美术最终状态只能是 ART_REVIEW_REQUIRED，直到 Owner 明确表示认可；不要把没有反馈当作默认通过。** 未经认可的艺术候选允许继续开发并测试，但不能定性为成品。
- 可以在不增加购买/外部发布权限的范围内完成常规 commit、push、PR 和通过现有保护规则的合并；每次合并前先复核状态与 CI。不要绕开仓库保护规则、强推、不审核地一次性堆积大量不相干改动。涉及大规模迁移时先备份可回退候选。
- CI FAIL/测试 FAIL 时先修实际根因，不用删除测试、降目标、跳过验证或伪造成功掩盖失败；如果无法在本轮修复，隔离变更、记录准确复现路径与后续优先任务。

## E. 自动审查不仅是“运行单测”

每个可玩的新版本都须执行以下自审：

- **技术**：Godot 导入/启动/游戏中不崩溃，测试与 GitHub Actions 通过，九武器及现有战役/存档主要回归没有下降。
- **玩法**：主角与军队真实移动，能够交锋、伤亡、胜负、撤退、战后继续，不因美术重建出现穿透、失手、原地滑步、将领瞬间胜利等伪战斗。
- **画面**：机器采集真实默认镜头 + 近/中/远，至少看清普通兵的四肢/武器/衣甲结构、环境的功能性、士兵与地形关系；有 30–90 秒正常速度、真实输入与完整战况的视频。新增内容不能只在素材浏览器里好看。
- **对标**：和仓库已有八款真实游戏示例按**各自对应维度**逐项对照；每轮列最严重 3–5 个差距，并至少解决一个真正影响游戏观感的根因。
- **性能和合规**：记录实际渲染配置/可见人数/资源变更/许可，不虚报“60FPS”“商业级通过”或使用非法素材。
