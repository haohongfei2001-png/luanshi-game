## 一、总目标：一款能打各种仗的战争游戏，不是固定两军对冲

游戏中不应每场战斗都变成“玩家与敌将决斗 + 两队士兵在平地互砍”，也不应变成地图上的文字事件或单个赢/输按钮。不同战场拥有**真实可感知的地形、地物、军阵、兵种、情报、后勤与双方军事目的**。对方也有真实主帅、战场主将、先锋、各级军官和精兵，世界继续独立演化。**军事胜负不等于杀到某百分比或斩首。**

**最重要的系统判断**：这些是具有共享军事规则的**不同战争情境**，不应全部做成各自硬编码、不能复用的一关。真正的敌方决策和实际军事力量能产生未写死的战果；可玩内容随战局而分支，正式文学剧情和人物仍全部由用户日后创作。

## 二、人员层级、敌方将领与有特色的兵种

**双方对称有相同制度上的潜在能力，并非每次镜像复制数值**：

| 层级/角色 | 战场可观察的责任 | 战斗能力与行为差异 | 风险与限制 |
| --- | --- | --- | --- |
| 普通新兵/民夫/临时兵 | 跟随编队、守点、搬运、修筑、护送 | 低成本 FSM，持有真实武器/HP/攻防/士气，可在屏内攻击防御逃跑 | 不具备通用高智能/魔法式战斗 |
| 训练有素兵、老兵/亲兵、精锐部曲 | 阵线骨干、护卫、战术突击、押运 | 更好的训练/装备/纪律/阵型保持/反应速度，不等于一定有军官权 | 受箭矢/包围/疲劳/补给限制 |
| **叫阵小将 / 少年骁将 / 精锐斗将** | 可能主动叫阵、挑战对方武将，带小股精兵突击、试探敌军士气 | **明显强于普通兵且可与玩家在真实控制战斗中交手**，武器专精、招式/时机/格挡反击；不是每人都需要独立完整战术规划 | 叫阵≠强制剧情单挑；可回应、拒战、乱战、护卫、退回阵中；击败或拒绝可影响局部士气/声望，**不自动判战役胜负** |
| **先锋 / 前锋将领** | 先行侦察/突击/开路/夺桥/试探/牵制，率先锋营接战 | 懂冲锋、阵型、选突破点、击杀小兵/对阵敌将，可能本人领先，也可能派前队 | 不必是全军最强；先锋损失会影响先机、情报、士气、续战能力 |
| 统率步/骑/弓弩/攻城/水军的将领 | 负责一个战术纵队、兵种或军区 | 兵种专长/阵地职责/个人勇武与统军能力分别建模，可实际战斗也可坐镇 | 离开己部、被切断命令、负伤会产生可观察的代价 |
| 战场主将、参谋/副将 | 分配军令、预备队、撤退或再攻、战场全局目标 | 比普通兵更强但也可能不以亲自杀敌为主；可委派和继任 | 受有限情报/通讯/补给/军心限制 |
| 全军主帅/军政统帅 | 负责战役或更大的军政战略，可能根本不在本次战斗地图 | 不一定最高个人武力；在后方调度、授权主将、安排援军 | 不能总被玩家看到或通过击杀结算战役 |

**将领属性至少分开**“个人武力/动作与兵器熟练度”“统军能力”“当下可用情报”“胆识/谨慎程度”“士气威望/号令能力”“伤势/疲劳”与“上级军令”，不以单一战力数值替代各自作用。

**常见兵种系统**（可组合装备、阵型和经验，而非无限新增互相重复的职业）：盾步兵、刀剑/棍兵、枪矛方阵、长刀兵、弓兵/弩兵、轻/重骑兵、侦骑/斥候、亲兵/护卫、工兵/攻城兵、辎重/运输兵、舟师/水军与战船人员（随技术时代解锁）、有时代和工业前置的火器/炮兵。不同兵种可互相保护或克制，但必须遵守实际队形、射界、地形、弹药、补给与天气限制。

**战术遭遇原则**：玩家可以找敌方小将/先锋正面搏斗，也可以绕过、拖住、设伏、救己方将领或无视；**敌将不会因此冻结**，仍可能穿透我军战线、杀伤友军或执行其军事任务。叫阵会影响声势与注意力，**绝不强制玩家与精英开决斗副本**，也不通过击杀叫阵小将立即获得战场胜利。

## 三、战争类型：同一套底层机制产生不同战斗

以下是**可供筛选的战术情境候选库**，不等于全部必须制作；仅对实际采用的玩法要求其机制产生可观察的战斗差异，而不靠换名称或空按钮冒充：

| 情境/场景 | 决定战局的真实系统 | 合法军事目标/结果 |
| --- | --- | --- |
| **平原正面会战** | 战线长度、步兵阵型、弓弩射界、骑兵侧击、鼓角、预备队和士气 | 突破、迫敌退军、夺取战场节点、保住主力、撤退 |
| **跨复杂地形的正面对抗** | 河流/桥、坡地、高差、泥泞/道路、隘口、行军速度、阵型展开 | 渡河、守桥/夺桥、抢占高点、保留交通线 |
| **夜间偷袭/夜战** | 照明范围、火把/营火、视野与听觉、敌军警觉与巡逻、误判/友军辨认、军令混乱 | 潜入、烧毁/夺取军需、救人/开门、袭营、撤离、守住营地 |
| **包围、反包围、突围** | 真实闭合/缺口的包围线、援军、退路、军心、粮水消耗、分队协同 | 迫降/断援、解围、保主力突围，可能双方都留有军队 |
| **据点防守、营寨攻防** | 工事、岗哨、侧翼、预备兵力、门道与可毁设施 | 守时、守住目标、撤出核心人员、进攻突破 |
| **守城、攻城、围城** | 城墙/城门/护城河、工兵、攻城器械、守军补给、墙上射界、内应、围困与援救 | 登墙、破门、夺城/解围、逼降、收兵、粮尽转移 |
| **山地、林地与峡谷战** | 可达路径/高差、密林遮挡、伏击/侦察、骑兵不利地形、弓弩射线、狭路车队 | 护路、伏击、控制隘口/高处、掩护撤退或突围 |
| **截断补给与水源争夺** | **城市/粮仓—道路/河道/桥梁—运输队—前沿营地—士兵**的真实粮、箭、马料流；水井、河源和营地取水路线 | 断粮/断水、夺仓、护粮、抢通道、击溃运输、恢复供给；不是切一根线立刻全军死亡 |
| **多个据点同时争夺** | 多控制点、分兵、侧翼、有限命令/情报、局部增援、独立敌方将领 | 多点控制、限时救援、取舍战略节点，**不是单个点被拿下就必然全局胜利** |
| **不同城池之间的占领/绕道/埋伏** | 世界道路和真实地形、守备和驻军、侦察报告时延、出兵与援军、后方城池与补给中转 | 围而不攻、绕路突击另一城、袭击联络线、守一失一、夺城后真实占领/驻防与治理 |
| **火攻与反火攻** | 可燃地物/辎重/营帐，风向/天气/湿度、实际火势扩散/隔断，防火和救援行动 | 烧毁设施/粮草/舟桥、逼迫撤离、反烧、扑灭；火势可以反噬进攻方，非一键全图秒杀 |
| **投石器械、工程机关和陷阱** | 适应时代的投石/破门机械、机关防御、工事与设伏位置、部署/维护/弹药，真实射界和伤害 | 破门/压制守军、阻路、伤骑兵、保护阵地；陷阱可侦测、拆解、绕行，不能自动必杀 |
| **河道水战 / 舟桥争夺** | 船只载员、靠岸、渡河、逆流/顺流、水面射界、操舟与登船、岸防和桥梁 | 夺渡口、断/护浮桥、护送粮船、阻断援军，舰毁/搁浅/逃走可改变后续陆战 |
| **海战** | 舰队补给、风/海况、船体耐久/火灾、编队和导航、舰上军令、接舷/射击、港口和舰队战术；技术发展后有火炮 | 护航、截断海运、封锁、夺港、突围、舰队失能/投降/撤退；不是两艘船血条耗尽的简化 Boss 战 |
| **火炮/火器逐渐出现后的战役** | 炮兵阵地与载具/舰船、火药/炮弹库存、装填、射线/后坐/精度、训练/制造/运输成本、技术代际差 | 破城墙、阵地压制、舰队决战、营防升级；**不得在初始唐式阶段无技术/工业前提生成成熟近代舰炮** |

**注意**：“城池和地形多样”并不等于首版必须先制造大量粗糙、互不联通的地图。最佳工程路径是**共享单位、战斗、地形/道路、目标、军令、后勤、天气/光照与火势等基本规则**，先把一张精细多地形战场完善为可重放测试平台，再逐步形成可配置的其他战场和不同城市的几何/防御差异。**全部列举的战例与战场类型是创作参考，不是游戏完成的强制检查表**；应挑选可玩性提升明显、复用性强的少数元素，其余可合并、简化、延后或不采用。

## 四、地形、据点、补给、水源必须真实影响战斗

### 4.1 地点不是装饰背景

为每张战场/战略地图建立**可通行与可控的地形及节点**，而不是只有视觉上的河桥/水井：
- 道路、桥梁、隘口、林地、山坡、城门/城墙、仓库、井/溪流/可取水区域、渡口和港口具有位置与可达性、容量/通行效率、兵种限制、视野/射界、占领者、损毁/修复、交通连接。
- 占领不同城市/营寨/桥头/粮仓可改变真实道路可用性、前线补给、援军到达时间与财政/兵源。驻守、经营、迁移库存和反攻都需要时空成本。
- 跨地形正面会战不仅调慢移动速度；地形应改变**行军队列、展开阵线、射界、伏击风险、撤退与战斗阵型**。
- 对多个据点争夺必须允许敌我同时行动。玩家不在的城池也会攻守变化；消息有时延，不能凭 UI 得到未来结果或远处确切位置。

### 4.2 物资通路是可中断的真实链

建议建立统一 SupplyGraph（函数名不是硬要求）：
- 节点：城市生产/粮仓/水源/驿站/营地/运输队/军阵的储备。
- 边：道路、桥梁、山道、河运、海运以及临时舟桥和中转，具备位置、容量、速度、风险、可用性及控制权。
- 流动：粮、饮水、马料、箭矢/弩矢、修械材料、火攻/攻城/火炮物资在**出发处扣减**，经实际运输后抵达；中途被截获或毁损不会在目的地凭空出现。
- 断粮/断水是**逐渐消耗库存引发后续后果**：先缺乏恢复/疲劳、士气与作战效率下降，后续因严重缺乏而病倒、散队、降服/撤退，符合军事情境，不能切路瞬时秒杀千军。
- 水源争夺包括饮用水供应、马匹/营地维持、船只/渡口与河道地形；不要求模拟每个士兵的个体饮水动作。
- 控制一座粮仓不等于立刻获得储粮；取用、搬运、守卫和运输皆有实际条件，守军也可转移/破坏/分散库存。

### 4.3 侦察、伏击、火势与情报

- 斥候、哨兵、夜巡、林地遮蔽与营火照明影响能否发现埋伏；双方受同一信息规则约束。未侦知的伏兵可以产生合理惊扰与军令混乱，**但不能为了剧情硬刷敌兵到玩家身后**。
- 夜袭有准备/撤离/误击风险，火攻受风/湿度/可燃物位置、灭火行动和天气影响；**玩家能判断风险并进行反制**。
- 工程机关、陷阱应是可以布置、发现、绕行、拆除和被失误触发的场景物件，不能因为玩家看不见就永远不能避开。现实器械的伤害可以近似计算，不能穿过实际不可穿透的建筑。
- 无需设计现实可操作的危险器具制作教程；此处只规定游戏机制和可测试效果。

## 五、跨时代装备：时代由生产力决定，不由剧情章节切换

本游戏架空历史以中晚唐式物质文化开局，又计划在同一主角的高成功长寿路线中经历压缩千年的军政技术演化。因此将“火炮/海战/战车”等以**年代、工业与生产基础**区别：

- **唐式初始战场**可有弓弩、盾枪、刀剑、骑兵、投石/破城器械、舟船/河战、火攻、普通工事和机关陷阱；战车作为架空小众装备而非该时代标准主力。允许战火与战马，不得直接配置成熟近代舰炮和现代火器作初始兵种。
- **火药与炮兵阶段**：原料、冶铸/加工、训练、火器、火药、炮弹、炮车、补给与安全风险逐步形成；早期火器和成熟近代炮兵是不同阶段，不得直接用“升级点+1”瞬变。
- **远期大型海战**：舰船吨位/船坞/航行与燃料/风/补给、船员训练、港口、海防与对手技术独立演化。陆战与水战共享军令、士气、物资与战争结算，但船的移动/损伤/战术需单独建模；无需强迫所有船员都用陆地一千人的逐人 AI。
- 即使玩家长期专注内陆战争，其他势力的海军技术与新军制仍独立推进；科技领先与否改变未来战争条件，不意味着自动胜负。

## 五B、唐末至清朝战史母库：器械分期的纠偏与高价值复用

**新增权威历史研究**：`HISTORICAL_BATTLES_TANG_TO_QING_RESEARCH_20261112.md`（20余个战例/战役群、兵装演进及历史来源分级）。Owner 决策见 `PRODUCT_DECISIONS.md §1J`；本文件军事场景类型仍全部有效。

- **唐末—五代**：重点不是复刻人物，而是军镇割据、先锋/精锐与混合步骑、城池与多方势力、粮道/援军/军令。重现战场因果，不把整段历史改成固定剧情。
- **宋辽夏金元**：军阵、边堡、河道—双城围困、骑射、抛石与早期火药军器。宋已有军用火药，12—13世纪围城、野战、水战应用火药并出现早期火枪/火铳技术，**不能把一切火药兵器放到清末**；但早期火矛不等于明代鸟铳或19世纪舰炮。
- **明代**：跨河湖舰队、火船与浅滩、城市守军/炮位、步盾枪弓/鸟铳混合阵、分路进军与集中击破、守城/援军、海上运输。
- **清前中期**：强大的常备军与地方军、远程草原补给、水草/马料、金川式山口碉楼、缅甸式热带丛林沼泽/疫病与行军困难、跨海登陆和地方财政军队组织。
- **清末**：沿海炮台与舰队、近代舰炮/机动和港口、城市长围、河运后勤、军工/训练/工业条件的军种代差；不可只提升一个武器伤害数字代表技术发展。

**技术状态应区分**：(a) 传统投石“炮”和火攻，(b) 宋元的火药燃烧/爆炸器材、火矛与早期金属火铳，(c) 明清的火绳枪/鸟铳、城防/野战火炮、后期更完善火器，(d) 清末工业化舰炮、新式枪炮、蒸汽与铁甲舰。**不是一个“唐代冷兵器→清末突然有火炮”的开关**。科技出现、推广、制造、训练、装备、补给、阵型和地域都可能彼此不同步。

研发时先从战史库提炼可重复使用的 `ScenarioTemplate`（地形、军种、任务与技术）、`EquipmentEraProfile`（器械、材料、可制造/部署及普及率）和真实战斗/补给结算，既有千人战场优先验收，不要求一次写完全部年代。

## 六、工程阶段与可验收输出（不擅自删减玩家范围）

**当前 Codex 已有 PR #17/#18 的代码工作**，不可因为新需求推倒重做；必须与千人战场、九种武器、将领 AI、WorldSim、存档兼容及 Mac M5 性能共同实现。

建议优先级：
1. **先在现有河关千人会战上增加兵种/叫阵小将/先锋角色，并让地形、阵地、粮道、撤退、战术任务真正影响局势**。可做平原推进、桥/坡/关口争夺与城门守攻的不同条件场景，最大化复用原地图和原兵制。

3. **先实现可复用的河道/渡口/舟船战斗**，与地面战场补给/桥梁/交通相连接；再做更复杂海战与舰队指挥。
