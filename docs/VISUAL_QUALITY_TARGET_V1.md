# 《乱世》视觉品质目标 V1｜先建立真正的美术基础，再扩展全军

**2026-11-12｜战斗首版 P0 美术质量任务；2026-11-13 Owner 更新画风方向**

> **更新优先级**：美术呈现以 [2026-11-13 视觉方向](ART_DIRECTION_CEL_SHADED_BATTLEFIELD_20261113.md) 为准；此前的“必须有真实 PBR 材质/不能使用卡通色块”不再有效。保留此文件对游戏内实装、角色装备结构、动作、LOD、真机性能与真实验收的要求。
**目的**：纠正河关 RC2“功能闭环已形成，但实际游戏画面仍显粗糙”的问题。此文档是可执行的游戏内视觉质量标准，不是概念图需求，不是剧情/世界观创作，也不要求做成 AAA 体量。

## 1. 最重要的裁决

**当前首要任务是把真实游戏画面做精致。** 不应继续把主要开发精力放在新增战场功能或只修几个战斗小问题上，而忽略人物、服饰、武器、地形和整体材质仍然粗糙的根本原因。

美术方向已按 2026-11-13 Owner 确认改为：**3D 国风动画式卡通、连贯大色块、简洁硬边阴影、克制描边、远近清晰的军阵**。不做 2–4 头身萌系玩具、塑料感、厚重油画纹理或密集 PBR 微细节；仍保留可信的服饰、装备、人体结构、负重、动作和历史战场气氛。

**优先级：真实游戏内视觉品质 > 单纯增加多边形/特效数量 > 增加更多地图和玩法。** 视觉资产必须进入正式 Godot 游戏，而不是只交 Blender 渲染图、AI 概念图、网页画廊或孤立展示场景。

## 2. 当前基线诊断（从 main 代码结构确认）

当前主线主要通过程序化几何构造人物和场景：
- `scripts/field/figures.gd` 通过 `mesh_builder.gd` 的 rod/block/loft/quad 等基础几何构成人物头、躯干、四肢和服饰；
- `scripts/field/figure.gdshader` 通过顶点弯曲表达步行、攻击、格挡、受击和倒地；
- `scripts/field/presentation.gd` 使用 MultiMesh 分组绘制近景、远景、阵列模型；
- `scripts/field/landscape.gd` 程序化生成地面、河道、植被、城门、营寨和冲车。
- 当前正式资产树里没有成体系的角色 GLB/GLTF/FBX、可复用骨骼动画库或材质贴图集；人物与场景的大量视觉细节来自代码生成几何。

**因此，粗糙感不只是光照参数不够好，而是角色、材质、服饰、动画与环境资产的基础表现方式需要升级。** 不要只通过调整 shader、加阴影、增加粒子或拉高多边形数来掩盖资产结构不足。应保留当前高效批量渲染架构，逐步替换/增强核心视觉资产。

## 3. 视觉目标与审美边界

### 3.1 人物比例和质感

- 保留“小模型/战场沙盘尺度”的视觉语言；不把角色放大到屏幕上占据大量面积。
- 在实际游戏常用镜头距离，能够辨认头部、脸、手、身体姿态、衣服层次、盔甲轮廓和武器持握。
- 身体结构有合理的肩、肘、腕、膝、踝和重心；攻击/奔跑/受击时有重量感，不是几根棍子摆动。
- 皮肤、头发、布料、皮革、木头、铁/铜、绳索和石材以清楚的色块、不同明暗等级、局部高光与轮廓体现差异；不强制微观 PBR 真实反射或复杂噪点，也不能粗糙得像同一种无层次的塑料。
- 面部可以简化，但不能只是一颗无辨识度的几何球；发髻、头巾、头盔、胡须等应有清晰轮廓且符合时代和兵种。

### 3.2 服饰与时代可信度

- 以唐末至架空古代早期的生产力为起点。普通贫民/新兵主要是粗布、麻布、旧衣和简单皮革；有钱人服饰可以稍好，但不应现代高级奢侈或满身金饰。
- 士兵护具应有实际生产力约束：布甲、皮甲、札甲/简易铁甲、头盔、护臂、盾牌按身份/兵种/资源不同组合。不是每个士兵都穿完整重型精钢板甲。
- 精锐、亲兵、先锋、将领通过更好的装备、剪裁、护具、旗帜、坐骑和姿态体现身份；不靠发光、巨大肩甲、奇幻纹章和夸张身高。
- 同一军队允许装备不齐、布甲破损、颜色和材质略有差异；战损后装备状态能有变化，但不要求给每名士兵手工独立贴图。
- 后续时代装备按历史与游戏世界技术条件逐步变化；不把宋元火器、明清鸟铳和晚清舰炮混为同一种外观。

### 3.3 武器与持握

- 九种已有武器：剑、刀、棍、枪、长刀、弓、弩、剑盾、双剑。每种武器要有可信的长度、重心、材质、握柄、护手、弓弦/弩机等视觉细节。
- 手掌必须真正围绕握柄/弓身/盾带，手腕、肘和肩关节与武器动作相连；不能出现武器悬浮、穿手、从身体中穿出或攻击时手握位置漂移。
- 长兵器和弓弩的轮廓在常用镜头距离可识别；武器尺寸与小人比例统一。
- 骑马与战车已有功能保留，提升马匹体态/马具/缰绳/鞍具、车体结构、轮子、轴、牵引关系和乘员动作。

### 3.4 场景和环境

- 河关地图不必马上扩大成开放世界，但河流、岸边、桥梁、道路、坡地、城墙、门楼、门洞、营寨、帐篷、粮车、冲车和植被需要形成统一材质、尺度和构造语言。
- 地面不能只是单色平面；有适度土壤、石块、草木、车辙、泥地/道路区分和地形变化。材质细节需在镜头高度仍然清晰，而不是放大后才有细节。
- 城门/城墙要有结构厚度、木石材质和可信的门楼构造；屋顶遮挡需要视觉上自然处理，不能把建筑切掉得像调试模式。
- 植被、营帐、旗帜、器械有规模和材质变化，但避免无意义装饰和重复素材明显铺贴。
- 天空、环境光、太阳方向、阴影、雾/远景层次要统一；不依靠强 bloom、夸张粒子或高饱和颜色营造“高级感”。

## 4. 动画质量

保留现有九种武器动作逻辑与实际命中判定，逐步提升真正的动作资产/骨骼姿态：
- 待机、行走、跑步、转向、急停、冲锋、持盾防守、格挡、闪避；
- 各武器不同的起手、攻击、收招、连击和恢复姿势；
- 弓/弩拉弦、瞄准、发射、装填；
- 命中、受击、硬直、后退、失衡、倒地、死亡；
- 骑马步态/转向/攻击/下马，战车牵引/乘员姿态/转向/攻击；
- 不同士兵不能完全同一相位同步摆动；可通过动画相位、速度和少量变体增加自然感。
- 动作必须在正常游戏速度与镜头距离可读，不做只适合静态近景截图的繁复动画。

## 5. 战场视觉层级与 LOD

采用可扩展的三级或多级视觉层级，保持当前 MultiMesh/批量渲染优势：
1. **近景**：玩家、敌方强将、叫阵小将、先锋及玩家附近交战单位，具备可辨识面部/手/服饰/武器、真实材质和较完整动作。
2. **中景**：普通士兵能辨认兵种、装备轮廓、武器类型和攻击/防御/行军姿态，使用较低成本的模型/材质/动画。
3. **远景**：通过有真实姿态变化的简化模型/阵列表现部队宽度、纵深、阵型和移动；不是静止标记，也不是无伤害假人。
4. LOD 切换不能突然变形、闪烁、丢失武器或改变军籍/位置；镜头快速移动时保持稳定。
5. 近景高质量模型与远景批量模型必须共享合理的比例、颜色、兵种辨识和动画语义，避免切换时看起来是不同游戏。

## 6. 光照、镜头和画面构图

- 保留易观察战局的俯视/斜俯视操作镜头，但让地形和人物有立体纵深，避免俯视过高导致人物成为无细节色块。
- 光照突出布料、金属、木材和地面的材质差异；角色不应被门楼/屋顶/树木遮挡得无法操作，建筑局部淡化或遮挡处理要自然。
- 阵营颜色清楚但克制；友军/敌军识别不能完全依赖大面积荧光色。
- 重要角色、玩家主角、军旗、冲车、城门和关键战线在常用视角可辨识，但不把 UI 做成覆盖半个屏幕的指挥中心。
- 实际战斗截图必须使用正常玩家镜头、正常游戏缩放和默认/推荐画质；不得用特殊近景/隐藏士兵/关闭阴影/静止摆拍来制造虚假品质。

## 7. 首轮实施方法：先做完整的视觉纵切片，再批量扩展

**先把一小部分做得足够好，再把标准复制到全军。** 但纵切片必须直接接入正式游戏和真实战斗，不是孤立 demo。

第一轮垂直切片至少包括：
- 玩家主角一个完整模型和一套完整装备；
- 一名普通步兵、一名弓弩手、一名精锐/叫阵小将；
- 一匹可骑乘的马及基础马具；
- 剑/刀/枪/弓弩中至少三类实际持握与攻击动画；
- 一段包含地面、道路、桥/河、城门/墙体、植被和营寨的正式战场区域；
- 同一画面内近景、中景和远景士兵的品质与 LOD 对照；
- 一段正常游戏速度的连续战斗录像。

Codex 应先建立一个统一视觉规范和资产制作流水线（例如 Blender/GLTF/骨骼/贴图/材质与 Godot 导入，具体工具自主选择）。资产必须原创或有明确可再分发许可证，不新增未经授权费用。可保留程序化几何作为远景/低端 LOD，但不应继续让所有关键近景角色只依赖基础 rod/block/loft 组合。

纵切片达到以下质量后，再扩展其余兵种、九武器、精锐、马匹、战车和完整场景。**不需要每个阶段停下来要求 Owner 逐项批准普通美术选择；最终提供可直接观察的实际游戏证据给 Owner 判断整体品质。**

## 8. 视觉验收

每次交付必须同时提供：
- 正常游戏视角截图（近景战斗、中景阵线、远景军阵、城门/冲车、人物特写）；
- 正常速度连续游戏录像；
- 近景/中景/远景 LOD 对照；
- 九类武器中已替换资产的实际持握与动作；
- 资产清单、来源/许可证、导入方式；
- 原始画质与性能档的内部渲染分辨率、帧时间 P50/P95/P99、内存；
- 同场景升级前后对照，证明不是静态展示或概念效果图。

**视觉目标不是照片级或 AAA 预算，而是在当前小模型尺度下做到精致、灵动、色块干净、结构可信、动画式质感，人物和装备一眼可辨。** 若新增高精度模型使 M5 性能下降，应通过 LOD、材质合批、动画降频和可见性管理优化，不应退回粗糙近景模型或削减实际军队人数。

## 9. 不要做的事

- 不要只调整颜色、加阴影、加 bloom、加粒子就宣称美术升级。
- 不要把角色做成奇幻重甲、塑料玩具、圆头卡通或高饱和 MOBA 小人。
- 不要只交 Blender 渲染、AI 概念图、宣传截图或网页画廊，正式 Godot 游戏必须真实使用资产。
- 不要一开始就重做全部 1024 个模型；先做少量高质量共用资产和 LOD。
- 不要为了细节牺牲镜头可读性、战斗手感、软密度和 60 FPS 目标。
- 不要让玩家管理额外的材质/装备细节或复杂 UI。
- 不要改写正式剧情；故事完全由 Owner 负责。

**首要验收问题：在正常游戏镜头和真实战斗中，这是否已经看起来像一款精致、有质感的中国古代战争游戏，而不是程序生成的低多边形测试原型？**
