## 1. 核心裁决：保留工程，不继承被否定的视觉基础

现有实机成果可以证明功能、命中、伤亡、构建或性能测试发生过，**不能因版本号递增、CI 通过或有录像就成为已获接受的视觉基准**。用户明确认为现有实机画面仍不合格。

- 不得把当前粗糙人物、装备、地形和界面作为正式视觉底稿，反复小改后自称完成。
- 不得仅通过配色、光照、雾效、描边、粒子、滤镜、提高分辨率或面数掩盖模型结构、动作、场景构造本身不足。
- 保留已有效的战斗、军籍/伤亡守恒、命中、军令、世界模拟、经济、存档和批量渲染工程；**重建不合格的视觉表现，不重启整个项目**。
- 旧资产/原型可保留用于隔离回归、历史对照；不得默认作为最终美术或新视觉合格依据。合格的新资产和已验证工程也不得仅因“视觉重置”被无差别删除。
- 禁止的是粗糙结果与重复敷衍，不是某种工具或文件格式。程序化制作、低面数、合批、LOD 本身不禁止，但必须通过实际镜头品质门槛；不能以“程序生成”“性能需要”为粗糙近景免责。

## 2. 视觉方向与目标不混淆

质量目标继续执行 [Owner 质量/流畅度/体量目标](OWNER_QUALITY_FIDELITY_PERFORMANCE_TARGET_20261113.md)：追赶《王者荣耀》级商业画面精度、制作完成度、清晰度、动作和流畅度；不复制其 IP 或未经授权资产。

**本次不是另一次画风切换。** 最新仓库已确认的 [国风 3D 动画式卡通/赛璐璐方向](ART_DIRECTION_CEL_SHADED_BATTLEFIELD_20261113.md) 继续有效；“可信人体比例、衣甲结构、重量和材质区分”不等于恢复早期微纹理 PBR 写实要求。不得借本次约束擅自切回旧画风，或把“卡通、简化”解释成几何拼装玩具和未完成资产。

角色在正常游戏镜头下应有清晰轮廓、合理关节与重心、可识别服装/甲胄/武器结构及持握；场景需要统一尺度、道路/地表/植被/城门建筑关系和自然接地光影。动作有起手、命中、恢复与受击，不以飘浮滑步、机械同步摆动代替。

## 3. 失败模式与判退规则

| 判退项 | 不合格表现 | 必须提供的替代证据 |
| --- | --- | --- |
| VIS-RESET-01 | 原有简陋几何人形/衣甲仅换颜色、材质参数或加描边 | 角色结构、装备剪裁/持握和动作在正常镜头与近景中实质改善 |
| VIS-RESET-02 | 空旷单调占位地形、机械重复物件仅加雾/草/阴影 | 连贯的地形、道路、建筑、植被构图与材质层次，且不遮蔽战斗 |
| VIS-RESET-03 | 只交概念图、Blender 渲染、资产查看器、摆拍或后期美化图 | 正式 Godot 战斗路径中的原始截图与正常速度连续操作录像 |
| VIS-RESET-04 | 用截图漂亮代替可玩、用 CI 绿灯代替审美通过 | 真实移动、攻击、命中、受击和死亡；工程与美术状态分别记录 |
| VIS-RESET-05 | 用低分辨率、隐瞒内部缩放/人数、最好一次平均 FPS 宣称达标 | 同配置前后对照，真实设备、输出/内部像素、人数、时长与长尾帧时间 |
| VIS-RESET-06 | 只有“更精致、更真实、更高级”等自评，没有可核查差异 | 被否定旧图和新实机同镜头对照、资产/动作替换清单、剩余缺陷 |

出现任一对应失败项，不得写“正式美术完成”“视觉已通过”或“已达到商业标杆”。如某项只是未测试，写 `NOT_RUN`；如画质未获认可，写 `ART_REVIEW_REQUIRED` 或明确“不达标”，不能用功能通过覆盖。

## 4. 用可玩的样板阻断低质量批量复制

沿用 [视觉品质目标 V1](VISUAL_QUALITY_TARGET_V1.md) 的真实游戏内纵切片流程：先建立一小块完成度足够高的战场和有代表性的角色/装备/动作，再把可复用标准扩展到全军。不能把样板当新孤立 demo 或整个游戏已完成。

“一个主角、双方各一种士兵、一小块战场”可作为最快检验方向的实施起点，**不是新增的永久兵种数、最终范围或对既有纵切片验收清单的削减**。具体制作工具、资产流水线和迭代顺序由开发者决定，无需反复询问普通细节。无须每个常规修改都等用户审批，但不得伪造用户对最终实机审美的认可。

每次视觉交付至少包含：
1. 正常玩家镜头、近景/中景/远景的原始实机图，以及正常速度连续战斗视频。
2. 同场景、同镜头、尽量同种子/战斗阶段的新旧对照；不同配置必须披露，不能偷换镜头。
3. 具体资产和动画替换清单、来源/许可证、导入路径及哪些旧粗糙资源仍在用。
4. 逐项通过/失败/未运行表；分别记录 `ENGINEERING_PASS`、设备实测状态和 `OWNER_ART_APPROVED / ART_REVIEW_REQUIRED`。只有实际明确认可才可写 Owner approved。
5. 画质与规模分别验收。小样本漂亮不证明千人性能；千人能跑不证明画质合格。继续保留 512v512 目标与真实世界结果。

## 5. 性能、合法素材和授权边界

执行既有 M5 目标：真实设备、内屏/外接屏、画质与输出/内部渲染像素、平均 FPS、P95/P99、卡顿及持续测试必须如实记录；托管 M1、Linux/headless 或短样本不代替 M5 验收。稳定 60 FPS 是基线，90/120 FPS 为高刷新率优化方向；不得声称原生 4K 最高画质千人恒定 120 FPS 已有保证。

可以自主选择合法原创或授权明确且可再分发的资产，改善模型/动画/材质生产方式；不得擅自购买素材、新增付费服务或突破预算。不可将生成概念图包装为实机图。此规范不授权访问用户本机、调用外部开发代理、改主剧情/核心产品方向或正式发行。核心人物与重大固定剧情审批边界、当前故事留空规则仍按最新产品规范执行。

**最终问题不是“比上一版好了一点吗”，而是“在正常实际游玩中，是否已摆脱被否定的粗糙原型，达到已确认的高品质方向”。**
