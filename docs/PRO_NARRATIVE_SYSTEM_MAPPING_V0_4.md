## 2. 能力账本：哪些可用，哪些仍需建设

| 能力 | 当前核验结论 | 对本提案的实际含义 |

| 物资与人口 | **已有局部模型。** 城市/军队有粮食、兵器、人数等，生产和消耗会改变实物 | 可写真正缺粮、运送与伤亡压力；当前没有因此自动成立的货币、借债、家庭财产和税权模型 |

| 延迟信息 | **已有报告基础，缺人物知识层。** 观察需实际条件，报告记录观察/到达时刻 | 可复用消息滞后语义；物理信使、截获、转述可靠度与各 NPC 独立知识仍须新增 |

### 2.1 三个不能偷换的既有数值

1. 当前 `WorldSimulation.VERSION` 是 **5**，存档封装的 `SAVE_VERSION` 是 **1**，两者不是同一个版本号。扩展时分别处理相应兼容责任。
2. `commander.max_hp` 的当前校验是 **360**，主角绑定 `relief`。这属于现有验证场景，不是十五岁新兵的已批准强度；不能只把文本年龄改成十五岁便宣称少年开局完成，也不能绕开校验偷偷换成100。
3. 默认随机种子 `184` 与本提案“晟历184年”只是数字相同，**种子不是日历**。当前时钟从场景起点计时，正式纪年需要明确映射。`MAX_TIME` 的一千年数值上界只约束计算范围，不证明能够流畅保存和模拟一千年，更不证明几十年人物生活已验收。

## 3. A／B／C 叙事如何接入世界

| 层级 | 作者可做什么 | 运行时依据 | 不允许的写法 |
| --- | --- | --- | --- |
| A 时代背景与结构压力 | 定义开局前史、制度、地理、既有权利和长期资源矛盾 | 已批准世界初值及制度规则；具体压力随真实世界变化 | 为让时代“继续乱”每年重刷叛军、取消和平、杀关键人物，或把未来灭亡写死 |
| B 重点重大节点 | 设计触发条件、参与人、利益冲突、可见场景、合法行动、多个后果与缺席版本 | 世界事实、人物状态、职权、位置、可达性与已获消息共同判断 | 先演完悲剧再补条件；以作者需要覆盖战斗结果；对话一选就无条件转移全镇 |
| C 普通世界事件 | 给事件提供表达模板和稀疏的人物细节 | 战争、物资、人物 AI 和时间真正产生的事实 | 为每个普通事件规定固定命运；让无权 NPC 获得全局情报或创造资源 |

重大事件至少要分开两层：**世界发生条件**与**主角可见/可参与条件**。前者满足而后者不满足，世界仍应处理该事；玩家以后可能收到过时、不完整的消息。主角不在场不等于世界暂停，收到报告也不等于获得当时在场者的全部秘密。

事件状态不宜只有“未接/已接/完成”。未来实现至少应表达：尚未具备条件、世界处理中、玩家已知但未介入、已解决/被避免、人物私线已关闭、结果仍未知。名称与数据结构由 Dot 依现有规范选择，本段不宣称有同名代码。

### 3.1 一次事件的合法顺序

1. 从权威状态核验事情是否实际发生或具备发生条件；确定人物的生死、身份、位置、阵营、授权及相关资源。
2. 根据主角掌握的信息决定是否显示、以什么措辞显示；未知对象不提前泄露姓名、数值和意图。
3. 只提供主角当前身份可以尝试的行动。高风险违法/违令可以是选择，但必须有真实执行方式与后果，不能因为“非法”就一律抹掉，也不能无条件成功。
4. 行动交给正式命令、人物决定或战斗系统处理。文本只能提出意图，不能自己替任何一方保证胜利、同意婚姻或交出军权。
5. 提交真实结果一次，再生成该结果允许的场景与记录。等待、赶路和战斗已经耗去的时间不得由结尾文案再扣一次。
6. 人物不参与时照常执行其有条件实施的行动；重大条件消失则延期、变化或取消节点，不为了消费内容人为补齐。

## 5. R01：罕见被俘归国支线的门槛

必须同时满足：**实际战败、主角存活、陷围且没有成功逃脱、真实捕获者在场并完成捕获结算。** 败退、失踪、匿名俘虏人数增加与主角死亡都不等于主角被俘。

现有结果及适配器没有提供完整可继续操作的主角俘虏生活。打开本支线之前，至少需要：保存主角存活与受拘束状态；确定拘押者和所在地；有限但真实的活动/知识/时间；能够通过实际交换、释放、营救或逃脱等条件离开；限制不能永久软锁；存读档一致。归国后的怀疑、重用或排斥需根据事实与政治处理，不自动触发通敌判罪。

优先级遵循最新生涯决定，排在青年军旅、小队、战争政治与主要关系之后。未完成俘虏机制时不宣称支线可玩；也不能借“未实现”把活着被俘的事实伪装为死亡，或把俘归设为认识岑望、进入内陆的必经门。

## 6. 最小数据责任：概念说明，不冒充已有字段

以下是新剧情需要被可靠保存的**信息类别**，不是已经存在的类型名或要求 Dot 原样复制的 JSON。应先对齐现行模拟契约，再决定如何扩展。

| 信息类别 | 必须能回答的问题 | 信息权限与持久化要求 |
| --- | --- | --- |
| 人物身份与时间 | 他是谁、何时出生、是否活着/失踪、现在的岗位与位置如何形成？ | 身份长期稳定；失踪与死亡分开；真实位置不自动全部给玩家 |
| 人物目标与关系 | 他需要保护谁、作过什么承诺、为什么拒绝当前建议？ | 保存事实与相关记忆；同一存档不能因重新打开对话随机变心；不靠全局好感值包办政治 |
| 职权与组织 | 谁任命谁、能命令哪些人、资源来自哪里、服从是否实际成立？ | 名义任命与实际控制分开；行为通过合法动作和执行者推进 |
| 证据与知识 | 谁目击、谁听说、消息何时形成/送达、谁可读取？ | 不把作者知道的动机自动视为角色知道；同一事件可有不同说法 |
| 社会关系与权利 | 婚姻是否有效、子女/收养关系是什么、共有资产谁能处分？ | 相互同意、年龄与既有关系需要一致性校验；新关系不删除他人已存在的人生 |
| 事件记录与结果收据 | 事情是否发生、谁已得知、哪项后果已提交、为什么没有触发？ | 稳定事件身份、原因、时间及一次执行凭据；避免加载重发奖励或复活人物 |
| 生平与结局视图 | 主角实际做过什么、临终知道什么、哪些仍未知？ | 世界事实档案与玩家可见生平分开；结尾只读取死亡截止时可知内容 |

普通 NPC 不必拥有与十名核心人物同样多的专属对白，但影响资源、命令或关系的事实必须可追踪。替补可以接任公职，不能继承死者的友情、婚姻、记忆和未公开秘密。新生或收养角色需有真实来源；不能为继承菜单临时制造孩子。

## 7. 事务、存档与长人生的工程边界

### 7.1 不能在 UI 里补发剧情结果

当前 `commit_and_save` 使用独立候选状态：在候选世界中结算，成功保存候选与收据后才接纳；失败保留原内存状态。重复完成请求可以返回已提交结果，`campaign_generation` 等约束用于拒绝旧世代结果。这个已有保障应继续复用。

未来需要随战斗落定的军功、关系事实、死亡记忆或任命，应由 Dot 接入相应原子边界和结果收据。不能先保存战斗，再让 UI 无收据地“关系+1、赏粮+20”；否则保存失败、重载或重试会造成一部分发生、一部分消失，或重复获得收益。

也不是所有长期后果必须在同一秒发生：抚恤、申诉或任命可以后来处理，但要有独立、可重试且不会重复的合法事件。正文只能引用已提交事实，不能暗中再写世界状态。

### 7.2 新字段必须同时进入校验与迁移

当前世界 schema 要求固定字段；城市、实体与战斗票据还有具体枚举/场景约束，事件审计也检查类型、顺序与账目。新增人物、官职、剧情收据、城市或阵营，至少涉及状态格式、schema、事件审计、存储恢复和旧档兼容的共同修改。把新内容塞进 UI 本地变量、未校验字典或任意事件文本，不能算完成持久化。

旧三城档案并不存在韩、罗、沈等人的几十年记忆。迁移不能捏造玩家“曾经恋爱、已经立功或曾经被俘”；可以保留旧验证档、明确标识内容版本，再以有来源的初值建立新的生涯入口。具体迁移策略由 Dot 按当前实现制定，用户已批准的存档权益与可回溯规则不因本提案取消。

### 7.3 时钟上界与长期可玩性分开验收

仓库记录的长期恢复证据包括90日历史及延续，不能外推为五十年完整人物模拟已经通过。当前历史数量、原始/压缩存档体积和审计遍历都有边界；持续追加事件最终需要保存语义不丢失的归档、分段或压缩设计，以及重新验证。不得删掉仍影响亲友、继承、军功争议或知识的事实来掩盖性能问题。

长时间相处、驻防或养伤可以用摘要呈现，但时间仍由世界统一推进。摘要应在关键危险、重大命令、婚姻/家庭决定或主角必须行动的节点中断。不能为了让孩子长大强跳十年，也不能让一段休养期间的战争和他人生活冻结。读文字或打开菜单不额外征收行动时间；世界未暂停时仍照既定规则运行。

这只是依赖顺序建议，不新增工程阻塞，不要求 Dot 放弃当前任务。Owner 未审定之前，Dot 仍可完成已经授权的机制与占位内容。
