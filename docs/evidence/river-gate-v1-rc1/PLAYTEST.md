## 战役和军官的实际结果

- 护送局中，先锋先打开城门，役兵仍能把冲车送到门洞。第 724 步取得「护送冲车成功」，内庭控制 0.0 秒，守军保有城池。普通兵阵亡各 174 / 232。[护送结算](journey-escort-report.jpg)

- 自行交战的攻城样本中，首击城门在第 517 步，破门在第 629 步。1 次就地补充役兵，第 1015 步占庭，普通兵仍有 249 / 208 人生还。另用原生界面分别打出了「成功撤离」与「主将阵亡」。

- 平陵巡防从三城军籍领兵，行军 3 小时后抵达，沿途世界处理 3 支车队。实出普通兵 27 / 14，军官 1 / 1，己方留下 31 名未参战人员。撤离后随军 34、后卫 26，军械共 30。无效来源存档被拒时，正在玩的世界得以保留。另测 641 / 389 普通兵共 1065 个持久身份，战中存读一致。[巡防军议](journey-patrol-muster.jpg)

- 双方军官会独立出手、发令、保护及接任。受控决斗中同一招在暴露、格挡、移出距离时伤害分别为 35.85、7.89、0.00。亲卫花 57 个模拟步救离伤将。双边交锋样本记录双方各 1 次击杀。双方主将均倒下后各发生一次继任，幸存士兵继续作战。俘获、护送者阵亡及伤亡入账另有独立回归。

- 兼容回归使用 #24 的原版进程写入 v3 存档。新版从第 161 步接续至原版自然结束的第 235 步，比较的旧版字段差异数为 0。旧三城、生涯和营地的存读检查也在主线工作流内。

## 画面、密度与剩余质量问题

同一批 512 对 512、10 个相机姿态对照中，前版军官细节和本版远处军官 LOD 的图元数分别为 243037 与 219323，软件渲染耗时中位数 76.8 与 67.4 ms。普通兵身份和伤亡计算在两组保持一致。[原始数字](measurements.json)

1. 城门仍有排队代价。同种子 3 米格峰值 42 → 19，士兵中心进入冲车车体的采样 394 → 0，破门后 6 秒内通行人数 144 → 59。重叠起步的 80 人能展开至约 669×638 厘米，半米见方峰值 4 人。后续应对照门外最后一列和门内左右侧的通行轨迹，提高分流效率。[前版同机对照含实录](../river-gate-formation-traffic/soft-density/)

2. 千人场的长尾帧和持续散热仍需验证。真实 MacBook Air M5 内屏和外接 4K，512v512 真实接战 ≥20 分钟均为 `DEVICE_NOT_TESTED`。已支持可选逐帧记录。后续应分辨模拟、渲染提交与像素开销，短时云端数据无法给出该机的持续结论。

3. 近景已有脸、手、甲片和握持，动作读法仍受近身人群遮挡，倒地人物与门楼投影有时相叠。从 [门洞图](journey-05-breach.jpg) 与 [持盾步兵](soldier-close.jpg) 可检查。下一次动作打磨应优先跟拍该处主角与对手的起手、格挡和受击。
