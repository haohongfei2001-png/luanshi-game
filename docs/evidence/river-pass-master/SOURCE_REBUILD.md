# Reconstruct the real candidate, not a simulated completion

The seed branch contains the frozen source, references, licenses and small text
files from local `bd9bf144e66c97bae3ddbea5dc2ab6811e7dcf45`. It is NOT a playable
candidate until the official-source workflow restores and verifies its raw
assets, builds the editable master and creates the integration branch.

The direct connector upload stalled on large binary requests. Four small fort
blobs and all text blobs were verified and preserved; no incomplete playable
branch was published. This alternate workflow uses the existing public hosted
runner and repository token, with no new account, paid service or user computer.

The exact CC0 nature ZIP and all selected members are hash-locked. The exact
pavilion archive and original FBX are hash-locked. Blender 4.3.2 and Godot 4.6.3
come from their official vendors with fixed checksums. The publisher free
pavilion download uses no account/payment; temporary CSRF/download addresses are
never printed or committed. No embedded script from an asset is executed.

Only `dot/river-pass-integration` may be created by the build; existence is checked
twice and the push is non-forced. main, PR61, RC24, RC25 and existing branches are
not overwritten. Generated resources and their actual hashes are committed
before pictures. `WORLD_SOURCE_SHA` is that actual commit, not the local expected
SHA or the seed. Differences from the local reference are listed, never hidden.

Lifecycle and real menu-entry tests precede publication. Actual game 2K/4K
pictures are delivered before the slower full regression suite. Still images
are not a normal-speed action movie, realtime performance evidence, M5 test or
owner art acceptance. Formal plot remains blank.
