## 2026-11-08 所有者九项创作决策：强制执行补充

**本节记录用户亲自确认的规则，优先于本文旧版中类似“建议”“默认”的措辞。** 九项的逐条原话语义及权限边界见 PRODUCT_DECISIONS.md 1B。若本文件以下旧段落与本节不一致，以本节为准。

### 1. 伤害成长，而不是血条神化
- **早期**主角与普通士兵力量接近，约可一敌二；没有早期清场“无双”技能。
- **成长路径**主要是攻击速度/威力、招式效率、攻击范围、武器品质、连击/破阵能力和对失序敌军的优势，使后期在百千人的大型战场里有可能**经过持续战斗累计杀敌数十至上百**，不意味着能一秒击倒百人，也不随战场人数自动获得数值加成。
- **防御约束**：血量成长设合理上限，不把“攻击强”直接变“防御强”。被多人近距离夹击、数十人的弓箭/枪矛有效齐射、被困地形和体力耗尽，仍可能快速战死。
- **平衡验证**：同一主角在“初期装备/技能”和“后期成套装备/技能”面对 1/2/5/10/30 名有组织敌兵时，记录杀敌与存活；后期能处理大量散兵，但在遭到有效集火时存活率明显降低。普通士兵伤害按可解释规则结算，不因面对玩家无故减少。
- **表现**：技能可覆盖多个低护甲敌兵，击倒应有动作/碰撞/士气反馈；不依赖超自然特效。

### 2. 军令物化为可以丢失的传递过程
- 本地可见队伍直接令旗/号角/近距口令，响应较快；远端通过有实际位置、速度、路线和风险的**传令兵**或其他时代合适的信号系统传递。传令兵可能遭伏击、被俘、迷路，军令无法送达。
- **命令状态机**：拟定 → 发出 → 传送中 → 已送达/已确认执行/被拒绝；可能出现超时无回音、传令失联或任务已过期。系统可以告诉玩家“派出三日尚未回报/推断未送达”，但**不自动显示玩家无从得知的秘密截杀事实**。
- 将领即使收到命令仍可能因本人判断、利益和当时情报拒绝、迟疑或改行动；新军令应能替代旧军令，但有中途传送和过期的风险。
- 指挥的局部手感要顺滑：不是每按一次编队快捷键都必须派步行信使；将真实传令限制用于距离/时代规模合适的场景。
- **指挥 UI**展示目标部队、下达/发出时间、最后收到回报的时间、传令渠道以及命令确定性；战术暂停功能由 Pro/Dot 作为可调 UI 决定，不得制造全知视角。

### 3. 时间以关键活动推进，反刷重复劳动
- **游戏时钟不等同点击次数**。菜单、装备、普通对话、移动光标与短距离交互的额外扣时近似零；战斗仍有真实的战场秒/分钟，战略真实世界的物资与战役继续受统一时钟影响。
- 主要的显著年月增量来自**行军、候命、休养、训练等长期行动、围城等待及关键剧情推进**。剧情转场不是无因强制时间跳跃：要标注消耗、世界期间发生之事以及可能错过的消息。
- 玩家可选择“等待至天明/援军到达/伤病恢复”等可解释快速推进，而不必现实坐等几小时；不得靠按 UI 或循环购买凭空产生资源/能力。
- **不思进取也有变化**：玩家停在城里休养、选择不参军或放弃目标时，界面应提供无惩罚的日月快速推进与社会局势更新；不强迫玩家刷同一任务才能让世界动起来。若玩家始终不进行任何耗时行动，真实短时世界进程仍按播放中的世界钟前进，不应冻结一切。
- 不规定一局必须 10、30 或 50 小时；设计目标是支持选择/能力差异显著的人生长度，不以固定小时数凑内容。

### 4. 政治自由意味着“可以尝试”，不意味着“按钮即成功”
- 玩家能尝试从军、升迁、辞官、投敌、集兵、叛乱、割据、称帝、隐退或守护地方，但有实际人脉、军权、社会合法性、物资、支持者、敌人反应和必要时间条件。
- 所有尝试都应生成**可解释的行动结果**：允许启动、因权力不足无法启动、无人响应、部分响应、遭镇压、成功但有代价等；不提供完全脱离历史压力的和平生活线路。
- 早期“边境三城”可以仅落实少量选择，正式版逐渐扩大到政治转变与不同军职开局；不为了凑功能做一整套农场生活游戏。

### 5. 历史两层：时代强制，结局不强制
- **不可随普通选择改变的层**：架空王朝在战争时代，已存在并形成相互作用的边境冲突、朝廷/地方权力斗争、资源不足与人口压力；部分大势力会根据既有动机发起重要战争。玩家“不管”不会取消战事。
- **可改变的层**：战役胜负、攻守时机、城池归属、重要人物生死、军队倒戈、个人结局，及玩家在历史关键节点有足够影响力时能够改变的国家命运。作者不可以为了既定悲剧，在玩家已实际解除围城后强制重播“安平必陷”。
- **影响范围分层**：大部分普通选择只影响局部物资、士兵、关系或小范围战果；少量精心设计的关键事件按能力/势力/位置/时间/知识决定是否能干预宏观历史，而非简单对话选项“天下立刻改写”。
- **事件架构**：历史锚点（世界环境与重大外部行动）→ 局部动态战役与人物反应 → 条件性关键剧情节点 → 后续世界后果。历史锚点意味着“战争的结构性压力存在”，**不意味着任何预定将领绝不死亡、任何战役不可改写**。
- **避免重复**：跳过没有新局势/决策的重复刷怪战、重复征兵按钮与长时间空等。可用短篇文字/战报汇总日常；关键抉择与大规模战争才分配更高叙事成本。

### 6. 统一的文化与存档基准
- 用户已将此前东汉末—魏晋默认改为以**中晚唐政治、唐末藩镇格局与唐蕃战争经验**为主要架空参照；如合并不同年代强势吐蕃与晚唐中央/藩镇局势，明确它是虚构合成历史而非单一年份复原。保持装备、生产力与政治制度内部一致。
- 自由正常存档 + 关键人生节点回溯。读档恢复世界、角色知识、在途消息、随机种子；死亡结束当前局，不禁止重新加载。
- 叙事主旨经用户同意：个人有限生命与无法完全掌控的历史；命运有代价，不必强制苦难。

## 0. 必须建立的游戏体验

玩家生活在架空中国古代王朝的战争与权力更替中，从普通边军、军官或将军起步。玩家可以亲自用刀枪厮杀，也能够征募和指挥真实有粮草、装备、伤亡、士气的部队；离屏城池、将领、战争与政治事件不会因为玩家看不见而暂停。玩家会衰老、患病、受伤或死亡，人生无法无限延长。已知历史可以被玩家改变，但不知道的事仍会发生；同一场胜利可能带来新的代价。

### 三个“等权重”支柱的判定
- **A. 个人战斗**：角色移动、方向性普攻、3 左右的技能、装备/能力成长、受击/走位/围攻与撤退具有真实可操作性。不是点一下自动结算。
- **B. 统军战争**：招募、编队、配装、指挥、行军、补给、援军、守城、攻城，军队能溃散而不是只战至全灭。玩家的临场军令能改变局部胜负。
- **C. 世界模拟**：不在视野内的城池与人物持续行动，人口、生产、仓储、势力关系、情报延迟与岁月变迁影响战争，玩家并非全知。
三者均须在**同一局连续流程中**有不可替代的决策价值。工程排期可以先做 A 再做 B/C，但正式版不能把任何一个支柱简化为仅供观赏的菜单或固定剧情。

### 有意不做
多人竞技、魔法/神仙作为主玩法、现代工业链模拟、每个普通百姓的完整人格 AI、百万个独立细粒度 AI 同屏、不可追溯的剧本强制胜负、多代继承、把每一种生活技能都做成系统。

## 1. 场景与游戏态

**大地图/战略态**：显示玩家合理所知的地理、军队、城池、情报时间戳；可安排招募、配发物资、驻军、行军、侦察、征粮、任命与治理。地图存在真实道路、河流、关隘与距离；不把所有单位瞬移。

**局部战斗态**：斜俯视 3D 小人。玩家实时移动、攻击与指挥可见或可通信的附近队伍。战场从权威大世界读取参战士兵/装备/位置/疲劳数据，结算后原子化回写伤亡/战利品，不凭空重置单位。

**人物/剧情态**：对话、立绘、简短过场；展示角色明确知道的信息与推测，不允许玩家用系统菜单直接查询未侦察的敌军真实人数。剧情阅读可以暂停时间，防止阅读速度影响战争公平性。

**时间态**：统一的世界时钟。战斗秒级，行军小时级，供给/伤病/饥饿日级，农业/生产月或季级，年龄从时钟派生。战略暂停/加速可用；战斗时离屏世界同样经过相应世界时间，但按较粗精度结算。时间跳跃不能凭空消除正在进行的围城或信使任务。

## 2. 操作与交互（用户已锁定 WASD）

### 桌面默认输入映射（允许用户重绑）
| 输入 | 行为 | 约束 |
| --- | --- | --- |
| W/A/S/D | 主角在水平地面相对镜头移动 | 镜头跟随、角色面向和攻击方向是不同变量 |
| 鼠标在战场上的落点 | 瞄准与角色面向参考 | 鼠标指向战斗空间，不自动给全地图真实情报 |
| 鼠标左键 / J 备用 | 普攻 | 有前摇、可读击中范围、冷却/体力成本 |
| Q | 近战横扫 | 适合对付散兵，不能无限无敌 |
| E | 突刺/短距离突进 | 路径障碍、碰撞和风险可解释 |
| Space | 站稳格挡/防御 | 需有时机成本，不能永久维持 |
| 1/2/3（初期） | 命令附近队伍攻击 / 跟随 / 撤退 | 最终加入坚守/集结，通过命令 UI 可见 |
| P 或 Esc | 暂停 / 菜单 | 战斗暂停不代表多人游戏同步需求 |
| 滚轮 | 战场缩放（允许限制） | 拉远不会获得未侦察信息 |

技能键的 Q/E/Space 是 **Pro 默认映射**，非用户逐键确认。Dot 可以改善冲突、加入设置内重映射，但禁止默默改成以鼠标点击移动为主。

操作验收：新玩家不用阅读技术文档也可在 1 分钟内理解移动、攻击和三个技能；10 分钟内能发出军令并辨认部队是否执行。UI 需要指示技能冷却、军令状态、目标、附近部队状态、方向与撤退出口。

### 摄像机与视野
建议近正交斜俯视、柔和缩放与适度镜头平移。士兵占屏像素较小，但衣色、武器轮廓、盾、盔、持矛姿态和受击状态须一眼可辨。战术镜头不是全知；遮挡、烟尘、未侦察区域与情报时间戳决定真实可知状态。不要为了“真实”使视野过窄或镜头持续抖动。

## 3. 英雄与战斗规则

### 角色状态
主角具有身份/军职/势力归属、年龄、健康、当前体力、旧伤、装备、技能、属性、指挥权限、个人关系与已知情报。初期属性可只实现生命、体力、攻击、防护、速度、统御；最终数值由体验平衡，不把示例数值当历史事实。攻击受装备和身体状态约束；在恰当操作下可击败大量低训练散兵，但不能无伤穿透长枪阵、箭雨和包围。

### 基础战斗
- 方向、攻击距离、攻击前/后摇、打击反馈、伤害类型与护甲减伤是少量必要机制。
- 普攻与技能应承担不同战术用途：点杀、控制方向、突围或防守，不堆砌特效。
- 主角击败很多弱兵的爽感来源于范围、走位、格挡时机和敌人失序，而非纯血量膨胀。
- 伤害不会总是致死：受伤、失去战斗能力、倒地/投降、阵亡可按阶段先简化，再纳入伤兵与俘虏体系。
- 角色被围、失血或疲劳时应有公平而真实的失败风险；死亡结束本局。
- 技能升级是强化已有动作属性与分支用途，不依赖魔法或过量技能树。
- 首个原型已有普攻、扫击、突进、格挡，**继承且调优**，不要重写成另一种系统。

### 兵种与真实装备
第一阶段两队统一占位；下一阶段依次有长枪步兵、普通刀盾/近战步兵和弓弩/远程；骑兵在马匹、路径和冲锋判定验证后再加。兵种能力由武器、训练、装备、队形决定，不靠固定职业魔法加成。缺少武器的士兵可空手、借农具或作为辅兵；未配武器者不能自动变成制式枪兵。

### 伤亡与士气
士兵应至少分出可战、伤、死、俘、溃散/离队几个结局，逐步由原型的存活/死亡扩展。士气受到伤亡密度、侧翼/包围、将领存亡、疲劳、装备/粮食和目击友军溃逃影响。局部溃逃可传播但不得无因瞬间全军投降；保留重整、撤退、追击和救治的机会。

## 4. 军队、军令与大规模交战

### 编制
世界里有 Soldier/Detachment/Army/Commander 的可追踪层级；普通兵可按队、装备池和类别聚合，特殊老兵/将领可拥有独立记录。把部队配置**实例化**成近景士兵只是一种表现和局部模拟，不应永久复制资源数据。

### 军令
- 小规模：玩家对近身部队直接给“跟随、攻击、坚守、撤退”，响应快且 UI 有反馈。
- 扩军：把队交给将领，玩家设置任务目标/地区/时机；消息需要合理的传令时延。
- 远端将领按其所知、实力和政治动机自主执行或拒绝；不应该机械遵守导致必死的指令。
- 指挥权限基于军职、委任、关系或实际控制，而不是纯经验等级；拥有十万兵力不等于对每名士兵直接下达操作。

### 大战的技术表示
- **战略总兵力**可逐步变为十万、百万量级的数量状态；只在政治、人口、运输条件足以支持时存在。
- **战役参战人数**可以远大于同时在近景实际模拟的人数，分为战线/时段/波次/预备队，后台按同一规则累计消耗与伤亡。
- **可视 3D 小人数量**与画面帧率、寻路、CPU、动画、渲染和可读性预算匹配。20v20 仅证明小场景；目标扩大需 100v100、500+ 等压力测试，不承诺具体上限。
- 远距与近景交接需守恒数量、军备、士气与已发生损失；同一场景既有近景战斗也有后方离屏战况，不能出现双重结算。
- 阵型的作用来自前后排接敌面积、枪矛长度、遮挡与士气；早期只需方阵、散队、守点等简化行为。

## 5. 物资经济与城池治理

### 最小资源
粮食、武器、护具、马匹、人口/劳力。每项至少有生产/来源、当前位置、持有者、分配/运输、使用、消耗/损失与审计事件。具体刀枪、甲胄属于类型或品质差异，不必一开始建立矿业、冶炼、皮革、纺织完整产业链。

**全局守恒原则**：补给流动、缴获、仓储取用、配发和报废都产生带来源去向的事件；生产和粮食消费是明示的生成与消耗过程，不能靠菜单免费刷兵或装甲。招募人口须占用/减少城市劳力，影响之后产能；损失土地或人口会影响未来收成。

### 粮食系统
军队每日根据士兵、随军非战斗人员、马匹和补给条件消耗。缺粮的后果应经过缺口、疲劳、士气下降、减员/逃亡、病死等连续过程；短期缺粮不能无提示一帧秒杀全军。对临时征粮、掠夺的即时收益与民心/生产损伤要有清晰后果。

### 城市状态与操作
城池保存：势力、人口、兵源、粮仓、装备库存、生产量、运输可达、城防、驻军、稳定度、重要人物。玩家可以决定驻防、供给、征兵、救济/征发、是否守城或放弃。城池经营必须改变下一场战争，而不是无关痛痒的装饰性升级菜单。

### 行军与补给
地理上的路程、河道、地形、天气/季节可先以修正量表述；队伍行军需要时间与补给。兵少未必弱于兵多，补给、地形和士气可以让大战出现逆转。援军不瞬移。俘虏、伤兵、战利品需占用携行或运力（可晚些实现）。

## 6. 玩家不全知：情报、世界和 NPC 行为

### 事实 / 认知两层
- **世界事实**：发生在地点与时间的真实城池守备、粮草、战斗进度、军队位置、秘密谈判与人物意图。
- **人物认知**：经本人观察、斥候、使者、俘虏、传言得来的带日期、来源、可信度的推测或报告。
- 即使游戏界面能拉远，也不能免费展示未获知的情报；如果地图要标敌军，应明确“最后观测于某日”“约多少人”。

### 重要 NPC 行为
一个有名字的重要将领具有目标/价值观、个体关系、健康与状态、掌握的真实资源、**他自己已知的**情报、对局势的主观判断、军令与利益。用效用排序或明确决策树，在守、撤、援、议降、拒命、隐瞒、倒戈之间作选择。可能错误、迟疑或改变主意，但必须在事件日志里解释原因；不要只用一个 loyalty 百分比掷骰。

**主观胜率**和实际胜率不同：角色因误信某军将至而退兵、因家眷留城而死守、因士兵饥饿而议降，都可能合理。士兵是否跟随倒戈取决于自身与将领的关系、训练、军饷、处境，不应整队瞬间颜色翻转。

### 时间/事件顺序
城池在玩家不在时继续被围或抵抗；城陷落后，数日之前寄出的求援信仍可以到达。援军有行军路线与预计到达时刻，途中可遇阻。前后变化写入世界事件日志，剧情根据事实和玩家可知信息触发，不覆盖世界事实。

### 战史灵感
可从官渡战中粮道破坏、将领离心与投降的因果链，以及淝水传统叙述中的恐慌传播、误判与秩序崩溃获取**机制灵感**；战争史料的兵力数字不能直接当成准确模拟参数。使用虚构国家、地点和人物，避免照抄特定史实作为玩家不可改变的结局。

## 6B. 中晚唐式政治、俘获续玩与旧友分歧（2026-11-08 新剧情方向）

用户已选择参考中晚唐/唐末的**朝廷—地方藩镇—外部边境势力**关系，详见 PRODUCT_DECISIONS.md 1C 与 NARRATIVE_WORLD_BIBLE_V0_2.md。朝廷拥有可能强大的中央军、都城防务、国库和诏令体系，但会因边战、内部猜疑与地方争权出现实质性伤亡、粮费消耗或重整，**朝廷不是固定弱者也不是固定反派**。皇帝的愿望、监军的判断、臣僚的政策及各路将领的行动允许不同。

**俘虏不等于死亡**：主角活着被敌方俘获时，可在受限行动中继续经历转押、留用、拒降、交换、逃亡、获释与归国；时间、身体、兵权与旧友仍在世界变化。重新入境时是否受欢迎、被疑、被捕、报复或重用，取决于证据、派系、权势、过往行迹和朝廷实际处境。李陵/苏武只是对照性历史灵感，不能写成“苏武也受汉廷必然诛罚”或“投降自动触发家族灭亡”。**只有死亡才结束人生局**。

**关系变化不是一个忠诚度**：旧友与主角可能同袍、上下级、对手、异阵营官员、不同任务而别后重逢；共同伤亡、功劳归属、军权分配、野心/自尊、价值观、家族、谣言与自己掌握的信息影响关系。拒命不一定是叛乱，野心不一定等于背信；能反目也能和解。角色分离后在离屏独立行军、晋升、受伤、死亡，重逢须满足地点、谈判或消息相通的真实条件。

**重大人物定稿界限**：安平救援仍是机制验证场景；新的正式国君、外方领袖、核心旧友与最终主线未由用户逐项审定。Dot 可以发展人物 AI、监军/军权系统、俘虏状态机与条件性占位文本，**不能把 Pro 草案的人名与人物必死/必叛情节标注为用户已定稿**。

## 7. 年龄、疾病、人生与存档

角色年龄随世界时间单向增加；健康、疲劳、旧伤、疾病可恶化或康复。年老应逐渐影响体能/恢复/战斗风险，但可通过经验、组织能力和信任的部将保持战略作用。70 多岁可能自然死亡，但**不硬性设置 75 岁自动死亡**；使用随年龄变化的风险与具体病伤状态，保证有可解释的时间跨度和预警。

重要 NPC 可以衰老、伤亡、更换职位；一般兵按群体更新，不能要求每个普通士兵都拥有完整家庭史。主角在战斗、病痛、自然死亡后即时进入本局终章。

玩家可以随时正常存档并获得若干重大“人生节点”；每个存档必须包含世界时钟、权威对象、库存、待处理事件、消息在途、NPC 知识、人物健康、剧情状态及随机数状态。相同存档和相同决策尽可能得到相同战略结果；改动行动才引出新的因果。不得用读档生成“刷新忠诚掷骰”作为核心玩法。

## 8. 叙事：有作者的主题，但不锁死战役结果

作者给出王朝衰败、朝廷/边军矛盾、人物宿怨、家族关系和局势初始条件。玩家的行军、救援、守城、征粮、平叛、夺权能改变人物生死、城池命运、势力走向。重要剧情是条件触发，允许因人物战死、城已陷落、战争提前结束而跳过/变体。

**安平救援**作为可复用的三支柱**技术验证/条件性边境战役**（不是正式主线必经的第一章；正式人生优先从约十五岁少年从军和首功受挫开始）：
1. 在测试/符合条件的生涯情境中，一名已成长为边军小校的主角驻平陵，有少量士兵、粮草和装备，收到三日前发出的安平求援；24 岁并非正式开局的必然年龄。
2. 选择立即支援、先侦察、改行山路、寻补给、留守平陵等可行行动；只有已实现的系统才显示相应选项；
3. 安平独立守城、消耗粮食并作守/降判断，敌军也受自身补给与目标影响；
4. 到达时可能仍在苦战，也可能已失陷；玩家可接敌/撤退/围攻/谈判（按实际可行选项）；
5. 战后影响粮仓、驻军、关系、军权及主角人生，而非只播放“胜利/失败”文本。

必要的多个结局：主角早死、战场阵亡、守住局部、失去城池保存部队、上升军权或天下变局中的重大决策。结局只报告可合理查明的内容，对不知去向的人和遥远未来保留悬念。允许有成功且不苦涩的局部结局，但世界永远不保证完美。

## 9. 美术、声音和故事演出

写实比例、克制的细节、低魔/非魔法。贫民麻布、磨损与补丁，富者衣料/做工好但仍受时代生产约束；士兵军备参差、装备真实来自实际库存。视觉远景首先让玩家分清士兵所属、兵器类型、防御姿态和队形，而非人脸细节。合理制作模型 LOD、材质共享、批处理和低成本动画；表现允许特写立绘与局部动作但不必大量昂贵过场。

打击音、脚步、甲胄、号角和阵线溃退声用于解释战斗。音乐不必堆大编制史诗风。音画素材必须具有自有或可合法再分发的授权、记录出处，不用未授权商业游戏图片/音效。

## 10. 计算与架构

**权威 WorldSim**：City, Army, SoldierGroup, Character, Faction, IntelReport, EventQueue, WorldClock, RNGState。数据层独立于 Godot 视图；可以在 CI 无显示器条件下进行可重复模拟。局部 BattleSim 从 WorldSim 获取只属于实际阵营的兵、装备和状态，完成一次后通过**幂等的战斗结算事务**回写，不能重复执行获得两份战利品。

**View/Presentation**：3D 模型、镜头、音频、HUD 与立绘是 WorldSim 和 BattleSim 的表现。游戏逻辑使用抽象操作，例如 Move/Aim/Attack/IssueOrder，不直接依赖键盘或触屏事件。

**Narrative Conditions**：从世界事实、人物关系、情报、时间读条件，决定显示哪些剧情与选择；结果优先修改世界对象并产生日志，再播放对应文字。事件队列、独立军队行动与消息传递有固定执行序。

**Determinism & diagnostics**：尽可能固定世界模拟步长和随机流、显式状态版本、结构化事件、存档迁移方案；包括库存守恒、兵力变更和人物行动原因记录。开发调试全知面板只在调试模式展示，不在普通玩家视图泄露情报。

**性能**：当前 20v20 原型的敌我扫描/近距排斥算法为二次复杂度，不能据此宣称支持成千上万实时小人。每次扩张前做基准测试，按数据量采用空间网格、距离简化、编队级行为、实例化/LOD，并检查真正的帧时间与热降频。云端无显示可做 CPU 和行为测试，不得冒充 MacBook Air M5 真机帧率。

**引擎**：继续当前 Godot 4 GDScript；Mac 优先构建，iOS 未来作为独立移植评估。云电脑构建 macOS ZIP 不等于在 Mac 上验收。保持每次改动可恢复、可测试，不允许以大重写丢掉已验证成果。

## 11. 难度：困难但公平（用户已锁定）

- 敌我使用相同的生产、军队、时间与资源规则；难度不能通过虚假刷兵、瞬移援军、伪造消息使玩家必败。
- 玩家不知道全部事实，但可通过派斥候、传令、观察粮草、敌军动向和历史情报**主动改善决策质量**；错误情报必须有来源和可解释原因。
- 高风险行动应给可观察的风险线索，不要求显示精确概率。陷阱和叛变可以意外，事后必须能通过信使、日志或已掌握的情报复盘，而不泄露不该知道的秘密。
- 败局不总能挽回，失败应可归于有限资源、时间、误判、人物动机或战斗能力；玩家换策略可以改变某些战局，不承诺所有人都能救。
- 普通战斗与失败反馈可读，玩家能及时理解命令是否下达、执行与失败的原因。重大不可逆状态转移可提供可理解提示及合理保存节点。
- 可提供练习战、帮助、可调整 UI/输入设置，但默认不把“困难但公平”自动降成无风险游戏。

## 12. 可调参数与合理默认值

默认开局主角 24 岁、首个救援场景约 60 名可招募/编组兵、粮食约一周、两军先各 20 名近景士兵，均只是原型与第一段叙事的**示例**。军队容量、粮耗/天、士气阈值、年龄曲线、技能伤害和具体战役年份须根据实际体验和测试调参；不要要求 Owner 决定或将例子误认为必须写死的设定。

## 13. 实施阶段和完成门槛

1. **现有分支继续**：prototype/cloud-first-playable 与 PR #1 已有 20v20 headless 测试，不可丢弃。优先保证真实可执行打包、手感验证渠道、自动测试与文档一致。
2. **最小三城世界**：实现统一时间、物资与行军、敌军围城、消息延迟、离屏胜负和一次战斗结算回写，形成至少三条不同因果结果的自动测试。
3. **30–60 分钟完整垂直切片**：玩家从招募/接军令到行军、实时战斗、战利品、故事后果与可死亡/读档；NPC 有有限情报和合理行为。
4. **首个完整小型游戏**：连贯可开局/通关/存档/重玩，Mac 构建、音画、剧情、UI、教程、基本设置可用。较短游戏是交付中间成果，不能误认已经实现数十年大乱世。
5. **完整长期愿景扩展**：更丰富开局军职、更多相互影响的城池/势力、不同命运的角色、几十年时间推进、多战区军权、足够多的动态事件，逐项通过 FINAL_VISION_ACCEPTANCE.md 和 ACCEPTANCE_MATRIX.md。只有在可玩性和性能支持时扩大人数/地图。
6. **公开发行**：必须单独获得所有者授权；没有 Apple 设备验收或发行许可不能声称已正式发布。

任何阶段的缺陷修复、代码实现、普通知觉审美取舍不需要等待用户批准。只有 PRODUCT_DECISIONS.md 的 RESERVED 项必须询问。**通过自动化测试不代表 Owner 已认可手感**，这一事实记录但不阻塞其他自主研发工作。
