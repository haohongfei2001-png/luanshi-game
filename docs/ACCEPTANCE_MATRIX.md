# 《乱世》功能、质量与公平性验收矩阵 v1.0
2026-11-08｜Pro 编写｜所有者四项产品决定见 PRODUCT_DECISIONS.md｜Dot 负责实现测试并提交实际证据。

## 0. 如何使用

每一功能以 **必须的可观察结果** 验收，而不是“写了脚本/文档”。每行有编号、阶段、检查方法和期望结果。Dot 必须在项目状态表记录 PASS / FAIL / BLOCKED / NOT RUN 和实际测试证据。用户无需逐项参与；云端可验证部分由 Dot 自测，真实 Mac 操作体验标记为“需设备验证”而不是伪造通过。

阶段：G1=战斗原型；G2=三城模拟；G3=完整短篇；G4=第一款完整小游戏；F=长期正式愿景。重大修复若使旧测试失败，不得宣布阶段通过。

## 1. 核心战斗与控制

| ID | 最晚阶段 | 操作/条件 | 期望结果与证据 |
| --- | --- | --- | --- |
| COM-01 | G1 | WASD 四方向移动，鼠标移动至不同方向 | 主角在水平场移动，朝向瞄准点；**不是鼠标点击移动**。输入自动化 + 录屏/实际试玩 |
| COM-02 | G1 | 左键普攻或兼容备用键，攻击前/侧/后不同位置 | 合理方向命中、伤害/冷却与反馈；背后不应被前向突刺误中 |
| COM-03 | G1 | 连续释放扫击、突刺/短突进、格挡 | 三个技能效果、边界、冷却明确；不会无限连发/穿越危险障碍 |
| COM-04 | G1 | 指令“跟随/攻击/撤退”，含有损伤与已死士兵 | 有效部队响应正确，死兵不行动；HUD 表示当前军令 |
| COM-05 | G1 | 两队 20 人交战 + 主角参战，反复启动 | 可真实移动、接敌、攻击、伤亡、结算；无脚本直接把敌兵归零作为唯一胜法 |
| COM-06 | G3 | 玩家阵亡与退兵 | 阵亡结束本局；撤退使幸存者保留，可复盘损失 |
| COM-07 | G4 | 不看开发文档体验 10 分钟，指挥与战斗互相切换 | 镜头、手感、单位可读，明显知道命令执行与否；手动体验报告/短视频 |
| COM-08 | F | 较大军队的多队行动和军令时延 | 不同将领/部队根据范围、距离与认知执行，主角不能瞬间控制远方所有兵 |

## 2. 装备、人口与补给守恒

| ECO-02 | G2 | 从城甲运输 100 粮到部队乙 | 城甲减 100，运输链路/到货数量与损耗可追踪；不凭空在甲和乙都保留 100 |

| ECO-04 | G2 | 军队超出携粮行军，连续缺粮 | 先出现缺口/疲劳/士气下降，再按规则出现逃兵、伤病或死亡；非瞬间清零 |
| ECO-05 | G3 | 100 人征兵出城 | 城池相应劳动力/人口减少，部队增人，下一生产周期有合理影响 |

| ECO-08 | F | 连续多个城池交换粮食、兵力、装备 | 全局账本可追踪入出流量、生产/损失；在大军规模上数量仍守恒 |

## 3. 独立战争、时间、有限情报

| ID | 最晚阶段 | 操作/条件 | 期望结果与证据 |

| WRL-02 | G2 | 同种子，主角提早两天行军 | 与迟到版本可发生不同结果，时间差在行军和围城数据中可追踪 |

| WRL-05 | G3 | 玩家派斥候，敌方有真实行动 | 经过实际侦察与传信时间后更新可信报告；误差及来源可解释 |

| WRL-07 | G3 | 战斗一次，回大地图再加载战场/存档 | 死者不复活，伤亡/装备/战利品不重复提交，事件提交有唯一 ID |
| WRL-08 | F | 至少三个势力和多个城池自行交战数年 | 无玩家参与仍有稳定、可审计、不同种子可变的世界演进 |

## 6. 难度与公平性

| ID | 最晚阶段 | 操作/条件 | 期望结果与证据 |
| --- | --- | --- | --- |
| FAIR-01 | G2 | 围城有明确粮食、驻军、运输和进攻事件 | 胜负可解释，不会因玩家进入关卡就重置城墙和粮食 |
| FAIR-02 | G3 | 玩家因迟到、兵变或缺粮战败 | 失败后通过已知军报/军需记录与新增可查情报，能理解主要原因；不直接暴露角色永远不可能知道的秘密 |
| FAIR-03 | G3 | 重试同一节点但更早侦察/运粮/改变军令 | 至少一场原本失败的局势在合理范围内可被改善/改变，不由脚本强制回归唯一结局 |
| FAIR-04 | G4 | 对比敌我同类型部队的行动 | 资源、行军、士气和伤亡基本同规则；难度不能依赖凭空刷军、无时间援军或操控玩家不可见概率 |
| FAIR-05 | G4 | 冒险操作之前缺乏完全情报 | 至少有可主动获取的侦察/补给/角色信号；不要求全知但要提供合理的风险判断线索 |
| FAIR-06 | F | 主角战斗强、统军大，却面临晚年危机 | 不被“等级满了”消除时间、身体、粮草与权力制约；仍有策略性胜利机会 |

## 8. 阶段判定与“完成”层级

- **G1 原型通过**：COM-01..05、TECH-01..02 有实测证据。云端无 GUI 时允许运动/输入逻辑判通过但 COM-07 待人类视觉复核；不许把它写成画面已验收。
- **G2 三城世界通过**：ECO-01..04、WRL-01..04、FAIR-01 的确定性测试通过。
- **G3 叙事闭环通过**：ECO-05..07、WRL-05..07、NPC-01..03、LIF-01..04、FAIR-02..03 完成可演示的连续流程。
- **G4 第一款完整小型游戏**：有可从头到尾玩的故事、稳定操作、美术/音效、存档与合法素材，达到本表 G4 相关结果；仍不能自动代替长期愿景。
- **F 长期完整愿景**：通过上表主要 F 项和 FINAL_VISION_ACCEPTANCE.md；容量和范围由真实体验与性能决定，不承诺百万 AI 近景同时模拟。
- **正式发行**：Owner 的商业、账号、Apple 签名、最终验收授权是单独条件，绝不等同技术完工。

## 9. 测试证据和失败复盘模板

每个测试记录：测试编号、Git SHA、Godot 版本、设备/云环境、命令/步骤、数据种子、预期、实际、PASS/FAIL/BLOCKED/NOT RUN、日志/录屏/截图/产物 URL。自动化覆盖世界状态与因果；图形可读性、操作手感和 M5 设备性能必须与 headless 分开。

对于玩家失败复盘，**展示角色当时有机会掌握的事实与因果推断**，例如“粮草只剩两日，斥候报告为四日前”，而不是全知调试界面泄露秘密谈判内容。开发者可另有全知调试日志验证因果，不进入普通玩家 UI。
