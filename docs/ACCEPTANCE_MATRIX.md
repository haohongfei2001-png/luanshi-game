# 《乱世》功能、质量与公平性验收矩阵 v1.0
2026-11-12 更新｜Owner 最新首版战斗权威见 PRODUCT_DECISIONS.md §1F｜Codex 为首要工程实施者，负责提交真实代码、测试、构建和 M5 性能验证状态；此前与叙事相关的长线验收继续保留，但首版剧情创作暂停。

## 0. 如何使用

每一功能以 **必须的可观察结果** 验收，而不是“写了脚本/文档”。每行有编号、阶段、检查方法和期望结果。Dot 必须在项目状态表记录 PASS / FAIL / BLOCKED / NOT RUN 和实际测试证据。用户无需逐项参与；云端可验证部分由 Dot 自测，真实 Mac 操作体验标记为“需设备验证”而不是伪造通过。

阶段：G1=战斗原型；G2=三城模拟；G3=完整短篇；G4=第一款完整小游戏；F=长期正式愿景。重大修复若使旧测试失败，不得宣布阶段通过。

## 7B. 所有者九项新决定的专项验收（2026-11-08）

本节是用户亲自确定的高层设计对应的测试。所有示例场景/阈值可以作为实施阶段的测试样本，不把“杀敌 100 人”当成固定难度公式。

| ID | 最晚阶段 | 测试操作或世界条件 | 必须出现的可观察结果 |
| --- | --- | --- | --- |
| OWNER-COMBAT-01 | G3 | 新兵/低技能主角与 1、2、5 名同等普通敌兵交战 | 初期有一敌一/一敌二的操作空间，但无法稳定无风险打穿大量敌军；量化伤害/生存/操作测试 |
| OWNER-COMBAT-02 | F | 高经验、高技能、好装备主角在百千人规模战役中依次击败散兵 | 可以凭更高伤害、范围攻击和配合溃敌**累计**斩获数十乃至百人，不是 AI 自动砍人或数值凭空随战场人数膨胀 |
| OWNER-COMBAT-03 | G4/F | 高阶主角遭 10/30 名敌兵从多个有效角度接敌/箭矢集中命中 | 血量有限、有效集火能致命；不能靠“英雄免伤 99%”把死亡机制架空 |
| OWNER-ORDER-01 | G3 | 近距令旗/号角给可见队伍下令 | 命令有可读状态，距离与遮挡条件合理，近距响应不被无意义拖延 |
| OWNER-ORDER-02 | G3 | 远方传令兵送信；对照一次正常到达、一次被敌军截击 | 信使的路线/到达时间/遭遇影响能否执行；未送达的军令不能被远方将领凭空执行 |
| OWNER-ORDER-03 | G3 | 传令兵在玩家看不到的位置被截杀，未有回报 | 世界真实标记已损失；玩家界面只显示等待/超时/可知的失联信息，不能无因即时显示敌人截杀坐标 |
| OWNER-TIME-01 | G2 | 连续打开菜单、装备切换、查看信件、普通短操作 | 不额外跳过几天，几乎不消耗世界时间；也不能利用零耗时操作无限产生生产/培训收益 |
| OWNER-TIME-02 | G3 | 行军三天、休养一个月、等待信使、关键剧情时间推进 | 世界统一推进粮耗、围城、其他角色行动、城池状态；不是只有主角年龄变化 |
| OWNER-TIME-03 | G4 | 主角不争军权、不接重要任务，选择长期等待/休养 | 其他势力仍发动战事/改变城池和人事；玩家受到世界变化影响，不停在静态世界 |
| OWNER-POLITICS-01 | F | 主角尝试辞官/投敌/割据/称帝等，但没有支持者/物资 | 可以失败、遭拒、只有部分人响应；无“按一下就拥有帝位和百万兵” |
| OWNER-HISTORY-01 | G3 | 玩家普通选择不参与安平救援，战略时间持续推移 | 乱世战争和其他军队行动仍发生，玩家不参与不会消除世界结构性冲突 |
| OWNER-HISTORY-02 | G3 | 改变救援时间、粮道破坏或守将接收到的情报 | 关键战役结果可变，游戏不能强行重放单一悲剧；同样的背景压力可以产生不同人物命运 |
| OWNER-HISTORY-03 | F | 无关键地位/资源的普通选择 vs 玩家具有军权、兵力与时机的关键节点行动 | 前者主要局部影响；后者才可能改变大区域战争与政治，且变化在世界日志中可追溯 |
| OWNER-PACING-01 | G4/F | 重复同一备战/野战/城池请求；玩家选择长期发展或不思进取 | 避免强制重复刷关、无意义长等待；世界能靠正常推进/事件推动故事而非固定游玩小时数 |
| OWNER-SAVE-01 | G3 | 任意合法场景存读档与人生节点回溯 | 同一真实世界与种子恢复，死亡结束该局但玩家可以回到过去；没有强制铁人机制 |
| OWNER-CULTURE-01 | G4 | 检查平民/富户/新募兵/老兵的装备/建筑/社会细节 | **中晚唐式服饰、装备和军镇**为主要物质参照，唐末政治与早期唐蕃战争合成时序注明架空；内部科技一致，不凭升级生成浮夸铠甲或超现实装备 |

专项通过要求包括 **(1) 世界状态记录，(2) 自动/手工可复现操作，(3) 真实画面/设备体验状态** 三个层面的证据；没有 GUI 的 CI 只能验证前两者。具体数值由 Dot 自主调参并在测试中记录，用户不必事先签署每个阈值。
