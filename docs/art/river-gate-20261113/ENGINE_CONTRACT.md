# 河关美术资产与现有战场接口

核对日期：2026-11-13（北京时间）。这是新资产的接入合同，不是对正式战役或性能的验收结论。

核对基线：`main = d5498a6b0e03528ae5f28a85ed98fa3ade758fd1`；另行只读核对正在开发的 `codex/river-gate-rc4 = 2293008c2d76dcbd788aeaef0fb871de1bc8eee1`。本交付不覆盖后者的活动开发。

## 1. 战场必须对齐的几何

地图平面坐标为 `(x,z)`，Godot 的 Y 是高度，单位为米。主线和 RC4 的 `scripts/field/ground.gd` 内容一致，必须由其逻辑决定可通行性。

| 地物 | 当前值 | 美术约束 |
|---|---|---|
| 作战边界 | x ∈ [-118,118]，z ∈ [-64,64] | 236 × 128 米是当前关卡，不是全游戏地图大小上限 |
| 河流 | 中轴 x=-32 | 实际阻水带半宽4.8；视觉水面可更宽，但不能暗示额外通路 |
| 三处桥面 | 中心 (-32,-35)、(-32,0)、(-32,35) | 桥面13.2 × 7.8；脚面 y=0.13；保留三处现有通行空间 |
| 西营 | (-83,0) | 帐篷、炊事、辎重围绕营地，不堵西撤线路 |
| 主关门 | (48,0)；门洞半宽4.0 | 实际通行阈值为门破后 abs(z)<3.7；必须保留门扇独立表现 |
| 内庭目标 | (66,0) | 夺关需要持续占领六秒，不能用装饰建筑盖掉目标区域 |
| 后墙与后门 | x=89；后门半宽1.65 | 保留后门与两侧绕城退路 |
| 南北墙 | z=±23，连接 x=48 与 x=89 | 不改变既有墙体碰撞与射线阻隔 |
| 城墙坡道 | x=49.4..52.6；abs(z)=5.5 起坡 | 按0.43坡率升至3.25米；保留墙上弓弩手通路 |
| 林地与高地 | GROVE=(-2,37)，RIDGE=(9,-36) | 林地减速、山脊高度有实际含义；地形表面使用现有高度函数 |

证据：[`ground.gd`](../../../scripts/field/ground.gd)；[`landscape.gd`](../../../scripts/field/landscape.gd)。正式主门、后门、桥头、墙梯和行军路线不得只按构图任意移动。新地图可以在独立预览中显示，但不可宣称已替换正式关卡。

## 2. 双方军容与实际兵种

当前双方是西侧进攻军（team 0）和河关守军（team 1），没有授权添加新的正式国家名、历史身份或文学人物姓名。既有游戏的区分色为进攻军靛蓝 `#394D66`、守军赭红 `#8E4B3D`。新设计可以以这两组色作统一识别；甲、皮、木、肤色仍按材质区分。

每个满编32人队的现有配置如下。弓弩兵、役兵、护卫仍来自这32人，不能再额外复制成战斗人数。

| 普通兵外观/装备 | 每32人队 | 512人一侧 | 对应 kit |
|---|---:|---:|---|
| 枪兵 | 5 | 80 | SPEAR=3 |
| 剑盾兵 | 3 | 48 | SHIELD=7 |
| 剑兵 | 4 | 64 | SWORD=0 |
| 徒步刀兵 | 4 | 64 | DAO=1 |
| 棍兵 | 3 | 48 | STAFF=2 |
| 长刀兵 | 3 | 48 | GLAIVE=4 |
| 弓手 | 4 | 64 | BOW=5 |
| 弩手 | 4 | 64 | CROSSBOW=6 |
| 轻骑刀兵 | 2 | 32 | DAO=1，mounted=true |
| 合计 | 32 | 512 | 将领和玩家另计 |

双剑 `DUAL=8` 是第九种玩家武器套件，当前默认普通队列没有双剑兵。角色资产应覆盖九套武器，但不能据此虚构九类默认步兵。四名冲车役兵从进攻军的既有队列挑选；每队最多两名盾卫和两名副手也从现有普通兵挑选。守军一部分弓弩手有 `wall_post`，直接站上前墙。

证据：[`battle.gd::setup`](../../../scripts/field/battle.gd)、[`arms.gd`](../../../scripts/field/arms.gd)、[`officer_corps.gd::setup`](../../../scripts/field/officer_corps.gd)。512对512是容量基准，不是全游戏人数上限或每局固定人数。

## 3. 将领不能只做一个双方换色大头人

| 实际角色 | rank | 当前武器 | 新资产需要表达 |
|---|---:|---|---|
| 战场主将 | 0 | 长刀 | 可辨识盔形、完整甲装、指挥识别物；比例仍是人 |
| 先锋 | 1 | 枪 | 近战轮廓与长兵器动作空间 |
| 叫阵骁将 | 2 | 刀 | 个人战斗身份，不添加强制Boss场地 |
| 精锐军官 | 3 | 剑盾 | 厚实护具、盾及合理握持 |
| 队正 | 4 | 剑 | 与普通士卒有细节差异，但不全员奢华装甲 |

512人一侧有16名带队军官：前四队依次使用rank 0..3，其余为队正；玩家另计。真实状态含受伤、撤离、被俘、阵亡、继任，不能让美术更换把命中、撤离或伤亡系统归零。当前玩家与军官视觉尺寸仅略大（1.07倍），不是巨人。叙事姓名保持空白。

## 5. 模型、材质与动作的现有合同

正式人群渲染通过 `company_art.gd` 从GLB提取网格，再按兵器、衣装、阵营、LOD合批；并非每人实例化一套Skeleton3D。

| 项目 | main | RC4候选 |
|---|---|---|
| 衣装名字 | Levy、Archer、Guard、Officer、Player | 相同 |
| 身体节点后缀 | Close、Line | Close、Line、Rank |
| 兵器节点 | Arms0Close..Arms8Close；对应Line | 仍用Close/Line，Rank身体配Line兵器 |
| 运行材质 | cloth_and_iron.png、surface_response.png | 相同路径，内容正在演进 |
| 动作库 | 16骨、32关键帧、16动作片段/武器 | 16骨、32关键帧、31动作片段/武器 |
| 皮肤权重 | UV2.x打包两个骨编号；UV2.y混合权重 | 相同编码，不能把UV2当普通光照UV覆写 |
| 人群实例 | MultiMesh，INSTANCE_CUSTOM状态/进度/步相/受击 | 保留步相、方向和LOD迟滞；近景与阴影分级 |

**不可把独立GLB文件直接替换 `river_company.glb` 并宣称完成接入。** 新资产若用标准glTF骨架，需在正式替换前重烘到当前动作/UV2合同，或明确新增经过实测的等效渲染路径。main的16片段纹理和RC4的31片段shader不能混用。不得批量加入每兵独立AnimationTree、布料物理或复杂碰撞。

九武器的动作时序、命中范围和技能以 `arms.gd` 为准；视觉必须对应蓄力→触发→恢复，弓弩有真实弹药。手与握点相合；枪、棍、长刀等双手武器要有支撑手，远近LOD保持同一动作相位。骑乘腿姿不得替代上身实际攻击。

新模型应提供源制作脚本、可编辑网格/骨架、实际三角面统计、材质数、贴图、LOD和真实Godot导入记录。数量与面数预算是设计指标；帧率必须在真实战役运行后另测。

## 6. 本套资产的验收边界

- `SOURCE_READY`：生成脚本、模型、材质和清单齐全，并可复现。
- `GODOT_IMPORT_VERIFIED`：Godot实际导入且资源无错误。
- `PREVIEW_RENDERED`：独立预览场景的真实引擎截图，可检查比例、服装、构图与LOD。
- `BATTLE_INTEGRATED`：正式战役真实加载且命中、动作、坐骑、伤亡和旧档回归通过。
- `M5_PERFORMANCE_VERIFIED`：实际MacBook Air M5在记录画质、窗口/内部尺寸后得到持续帧时；没有设备实测就不得标此状态。

概念参考图、Blender模型渲染、独立Godot预览、正式战役实帧分别标注。用户要求完整资产并不等同批准新的美术方向；交付应允许直接查看，不能把未审定参考图标为最终视觉权威。

## 7. 打开独立资产预览

在仓库根目录启动；场景通过 Godot 的 [GLTFDocument](https://docs.godotengine.org/en/stable/classes/class_gltfdocument.html) 直接导入GLB，因此可以在尚未生成编辑器缓存的新检出中使用：

```bash
godot --path . scenes/art_review/river_gate_review.tscn
```

`1` 双方列阵，`2` 角色近景，`3` 器械与环境模块，`4` 河关地图，`5` 1024个静态LOD2人物。`空格`切换待机/行走/攻击，`L`切换近景人物LOD，方向键更换近景角色；`WASD`平移、鼠标右键旋转、滚轮缩放、`H`隐藏说明。第五页仅把同一静态姿势合批绘制，不运行战斗、AI、寻路或伤亡；不能用它推算正式千人战役帧率。

复现真实Godot截图（输出必须是绝对路径）：

```bash
tools/art_review/capture_review.sh army /absolute/path/army.png 60
tools/art_review/capture_review.sh equipment /absolute/path/equipment.png 60
tools/art_review/capture_review.sh map /absolute/path/map.png 60
```

脚本支持已有图形会话，也支持装有Xorg dummy与xauth的Linux云机；后者使用临时授权cookie启动显示并在结束时清理。云机软件渲染的图像可以核对资产是否真正进入Godot，不能作为Apple M5帧率证据。每张PNG旁写JSON，记录引擎版本、图形适配器、分辨率、模型文件与镜头；缺少该视图要求的模型时拒绝生成“完成截图”。

需要指定角色或LOD时，直接传场景参数，例如：

```bash
godot --path . scenes/art_review/river_gate_review.tscn -- --art-shot=portrait --art-role=commander --art-lod=0 --art-output=/absolute/path/commander.png --art-frames=60
```

预览不会加载现有战斗类、存档或战役主场景，不会修改 `project.godot` 的默认启动入口。
