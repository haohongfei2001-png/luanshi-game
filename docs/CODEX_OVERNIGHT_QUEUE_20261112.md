在当前已经有双边基层军官、九种武器数据、千人战场模拟的基础上：
1. 为敌我双方增加真正的主将、副将/精锐将领、高层主帅/战场主将的区分；主帅可在后方且不出现在战场。
2. 敌方强将会杀伤我方普通士兵、攻击或压制友方将领，玩家即使选择持续屠杀普通兵也会因此承担战线风险；玩家与强将交手靠实际方向/技能/时机/走位等操作，强将可以护卫、受伤、被救下/撤退或战死。主角在合理条件下可以一当几十，但双方对称拥有高级战力，不靠夸张血条或敌方作弊。

4. 玩家死亡仍是本人生涯结束，但战争客观结果不应变成无因“敌方立刻胜利”；伤亡/继任/军令和俘获需延续到现有存档、战斗与世界状态。
5. 普通小兵继续轻量 FSM；高级将领数量少，可以使用更智能的战术/战斗 AI。真实代码、测试、性能和图形证据见 Issue #19。**与 PR #18 并发变更冲突时先让已有分支收口，再在独立分支补齐，禁止两个工作树争写相同源文件。**

## 执行策略：不要让巨大工作量使单轮成果丢失

1. 若 Codex 环境支持彼此隔离的执行上下文，**最多并行 A 与 B 两条任务**。它们分别使用独立分支与 worktree；不要让两个代理同时写 battle.gd、verify.yml、字体或存档迁移。若不能可靠隔离，**顺序 A → B → C → D**。
2. **每个任务都写可运行代码、跑实际测试、提交 PR 或可追溯 commit**。测试通过/运行画面/性能数据/录像应与对应实际 SHA 绑定，禁止只提交方案或自动生成的艺术效果图。
3. A 一旦稳定，就形成真实绿色 CI 与回退候选。B 每个兵员规模都保留帧时间、战损、摄像机移动连续性证据。C 每个武器先有可玩动作与真实命中，不只是配置数据。D 先证明真实任务目标能在敌军仍活着时结束战役。
4. 性能瓶颈先削减普通士兵的决策复杂度、独立寻路、频繁更新和远景骨骼动画；不优先削减 512v512 兵员或把普通兵变成静态假人。人形近景能分辨脸/手/武器/衣服，远景能分辨阵型。
5. 不用云端模拟 FPS 冒充真实 M5 表现。用户没授权 Mac 访问时，M5 性能验收是 NOT_RUN，其他可独立推进。
6. 不强制一次执行完成所有任务；尽可能推进有效代码。遇到困难，先隔离问题、保留失败日志、完成可独立验收的其他子任务，避免整轮无交付。
7. 每个子任务结束、上下文临近极限或执行中断前，把实际代码 push、对应 PR/Issue 状态、测试报告、硬件配置、下一条可执行命令以及未完成工作写入 GitHub。保留上一稳定构建，禁止强推 main 或盲合并未验证交接分支。

## 必须严格区分的状态

- CODED：代码已写但不代表运行成功。
- CI_GREEN：精确提交的完整 CI 已通过。
- RENDERED：实际游戏窗口可操作且有真实图形/战斗录像。
- MAC_ARM64：在具体 macOS arm64 机器上运行，不等于用户 M5。
- M5_60FPS：真实 M5 至少 20 分钟 512v512 战斗帧时间实测通过；未测不得宣称完成。
