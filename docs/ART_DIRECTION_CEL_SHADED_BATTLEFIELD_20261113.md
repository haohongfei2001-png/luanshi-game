# 《乱世》美术方向｜3D 国风动画式卡通与清晰色块（2026-11-13）

> **Owner 已认可的优先美术设计方向**（2026-11-13）。优先于此前“克制写实材质/PBR 真实细节是画面目标”的表述。**设计方向已确认；游戏内实装、视觉品质、动画和性能仍未验收。** 不把概念效果图当作 Godot 实机图，也不把图中临时 UI、标语、战役地名、旗帜文字当成已批准的功能与世界观设定。

## 0. OWNER-QUALITY-20261113｜视觉精度与产品品质提高

Owner 新要求**达到《王者荣耀》级或更高的画面制作精度、流畅度与完成度**。本文件的清晰色块、3D 动画式国风卡通与 Cel Shading 仍是正确风格，但**不能把“卡通”误读成几何简陋、贴图低质、硬邦邦玩具或粗糙 Low Poly**。人物近景必须有高质量的面容、手、衣甲结构及动作；中远景军阵必须清楚；场景需要统一、精致和真实可玩。游戏内实拍与连续录像优先于美术概念图；最终审美仍需 Owner 验收。

流畅度目标同时提升：M5 真实千人高质量交战稳定 60 FPS 为基础，90/120 FPS 与 120Hz 高刷新率为进一步研发目标，要求可复现的帧时间和真实分辨率记录；详细见 [质量权威](OWNER_QUALITY_FIDELITY_PERFORMANCE_TARGET_20261113.md)。

## 1. 设计裁决与真正要解决的问题

玩家希望《乱世》在斜俯视和大规模交战时，小人像**由清楚且连贯的色块组成**，角色与地图不会因油画质感、细碎笔触、微观纹理或复杂光影而糊成一片。玩家所说的“Q/卡通”指**动画式轮廓、平涂上色和适度概括造型**，**不**指 2–4 头身的大头萌系角色、玩偶或儿童化比例。

**选定方案：3D 建模和 3D 战场 + 中国古代动画式人物造型 + 赛璐璐 / Toon 着色 + 2–3 档干净的明暗色块 + 克制的轮廓强调 + 简洁但有层次的 3D 地形。**

不改成纯 2D 战棋或固定 2D Sprite 游戏；保留斜俯视摄像机、WASD 与鼠标操控、真实近战命中、成百上千士兵、军阵、将领、坐骑、攻城器械和批次模拟架构。**视觉表现可以卡通，战争行为、装备逻辑、伤亡后果仍应真实可信。**

## 2. 人物视觉语言

- **人体比例**：以约 6–7 头身为探索起点；非硬性美术尺度。可轻微突出头部、肩部、双手和武器以保证斜俯视辨识，不刻意做大眼睛或短腿萌系。
- **剪影优先**：长枪、刀盾、弓弩、骑兵、将领、前锋和主角的轮廓与姿态首先可识别；动作应有起势、发力、受击、收势及承重。
- **明暗和用色**：衣服、皮革、札甲、金属与木材由明确的主色面、硬边阴影面、少量重点高光构成；避免油画笔触、强反射、脏纹理、密集噪点、伪质感贴图和过量 bloom/雾。
- **描边**：深灰/深棕、局部且适度；近景可以强化关键轮廓，远景不必给所有甲片描线，避免千人叠线变黑团。不要把参考图中的线条机械地全部搬到 3D。
- **装备与阶层**：保留朴素布衣、旧甲、简单头巾、札甲、武器磨损、军需不足等具有时代和社会逻辑的差异；不因卡通而凭空让所有人穿华丽同款盔甲。
- **层次化模型**：近景主角和将领允许更多面容、衣甲、武器持握与动画细节；中远景减少装饰，只保留兵种/阵营/动作关键信号。不同 LOD 不能像变成了另一款游戏。

## 3. 场景、地图与全战场一致性

地图同样采用清楚的 3D 造型与色面层次：道路、草地、干土、河流、坡地、树林、城墙、营帐、城门、冲车和战旗具有稳定外形与明暗；降低不必要的地面高频纹理和抢注意力的颗粒。

地图**不是纯色平面**：要有可信的城墙厚度、地形起伏、建筑结构、植被层次及地形与部队之间的关系。保持适量深度、接地阴影和方向性光照；角色、武器、地面、建筑和 UI 在色彩组织与细节密度上应统一。

阵营可用旗帜、肩甲、披风和部队构型等共同区分，不能只靠红蓝纯色或仅凭线框标签；多兵种远景必须可读。

## 4. 从概念图到 Godot 的实施边界

- 游戏仍使用 Godot 3D 渲染与已有实例化/近中远 LOD/批次系统；可以先做平涂/分级光照的专用 Shader 和材质样板，不需要推翻游戏内核。
- 新材质**不是**换一层 2D 滤镜：必须从模型比例、轮廓、服装甲片的几何结构、材质分面、动作姿态、地图对比度协同调整。
- 不建议先制作上千名士兵的独立资产；先以**主角、普通枪兵、弓手、盾兵、精锐将领、坐骑及同场景城门/河岸**组成可玩的真实视觉纵切片，再复用模型骨架、材质和动作扩展。
- 保留可批量渲染的模型和动态实例，优先共享材质、贴图图集、材质参数与动画资源；实际性能按 MacBook Air M5 真机帧时间、内存和可见单位压测评估。
- 不要把生成概念图的 AI 拼写错误、UI、唐字军旗、固定阵营色、人物具体长相、标题、兵力密度、箭头、技能格子等作为工程“精确还原”需求。这些是展示语境，不是产品规范。
- 当前参考图仅用于**色块、轮廓、动画式造型、地图层次、军阵可读性**的整体审美沟通；不可直接当成可运行资源包、工程验收证据或用户已批准的最终 HUD。

## 5. 最小且充分的验收

1. 同一真实 Godot 场景、同一种子/机位/时间/兵力下，提交旧写实材质与新卡通平涂的 A/B 截图和短视频；**以正常玩家镜头**为主，独立人物原画不能替代。
2. 在**近、中、远**三档游戏相机距离，分别展示主角/将领、常用兵种、武器和密集军阵。远景首先判定是否能分辨人形、阵营、兵种、朝向与攻防动作。
3. 交战、攻城、河岸、树林场景不出现因密集描边、过高地面纹理、背景对比、粒子烟尘而导致的糊团。
4. 保持此前的战斗规模、性能目标与因果模拟，展示真实设备帧时间和性能；未跑 M5 真机则写 `NOT_RUN`，不宣称 60 FPS 已验收。
5. 美术最终认可由用户基于实际游戏内画面决定；**这次认可的是方向，不是整套游戏美术已交付。**

**一句话标准：远看像清晰、成阵的动画战场；近看是有可信服饰、盔甲、重量与动作的古代人物；人物与地图由干净的色块组成，而非厚涂油画或玩具塑料。**
