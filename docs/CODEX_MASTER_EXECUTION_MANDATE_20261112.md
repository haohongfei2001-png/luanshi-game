## 最新 Owner 规模纠正（2026-11-12；优先于本文旧文案）

**立刻读取 `docs/PRODUCT_DECISIONS.md §1L`。** Owner 不希望人为锁死战场面积或一场战争可存在的人数。**512v512 只是衡量最少 1024 名独立士兵能否同时在同一战斗实例持续存在/行动并按实际战况结算的性能验收场景，**绝非每场战斗固定人数、场景最大容量或必须 1024 人全部同屏。

- 河关一张地图是首个品质样板，不是最终世界里唯一能容纳战争的固定 MOBA 大小区域。实际战场范围由地理、双方军队位置、攻守目标及行军/突围决定，地图可按需更大或更小、分区加载、远处可靠持续仿真。
- 一场战斗可以几十、几百、上千乃至更多人；人数来自世界军籍和兵力部署、不会为满足 512v512 压测凭空刷兵，也不能超过 1024 就硬拒绝或删人。
- 远处士兵无须全部逐帧近景渲染、无须同时交战，但他们**必须实际存在**、保持身份/位置/命令/伤亡/装备，镜头外的时间与战事继续；镜头移动过去可自然恢复细节，禁止冻结或装饰假人。
- 仍然必须有 **512v512 的标准压力验收**与真实 M5 60 FPS 目标；这是**容量/性能最低可验证样本**，不能冒充无限硬件能力。用分层更新、共享小队 AI、LOD、地图流式加载等技术优先降低计算成本，报告真实设备规模上限和未知项。
- **不要为此推倒现有河关 PR 或改成开放世界工程**。在已经实现的战斗和世界/存档机制上修改硬编码人数/战场面积假设，新增大小规模/跨不同战线的回归；玩家体验和易用性继续第一。

## 最新 Owner 关键纠正（2026-11-12）：局部软密度，允许近战贴靠和视觉重叠，拒绝大规模同点堆叠

**以 `PRODUCT_DECISIONS.md §1M` 最新 v4.2 为准，撤销此前把‘每个人的完整身体都不能有接触和重叠’当作物理硬约束的误读。** 玩家允许几名士兵靠得极近甚至模型/粗粒度落脚点部分重叠（尤其斜俯视的前后排），**但不允许几十、几百或上千名单位全挤在同一个极小区域或坐标，失去实际军阵厚度**。

最高优先级仍是修复河关冲车与城门拥挤、行军与接战时的视觉重叠问题，**方法为局部软密度限制而非严苛的逐人硬碰撞**：

- 复用已有空间网格；按邻域人数/占地权重、步兵/骑兵/车辆、地形通行有效面积作轻量密度估计。允许少数近邻贴靠/局部身体或脚下投影交叠；超出合理局部拥挤程度后，**渐进减速、缓和分离、外围排队、选择可用站位或自然扩张阵型**，阻止大量单位持续堆同一点。
- 不要实施“每格只能容纳 1 人”、每帧所有人两两刚体碰撞、超过小密度即瞬移或把士兵弹走、必须完全消除模型交叠等昂贵/反效果方案。适当视觉重叠与两三名士兵混战是合理的。
- 必须让实际军阵看上去有**左右宽度、前后纵深、合理通道拥挤和兵力人数感**；桥/城门仍是战术瓶颈，但不可无理由永久堵死。主角能够贴近敌军操作，士兵可以围攻或组成密集盾阵。
- 若合理密度下目前近 MOBA 尺度地图容纳不了千军展开，就扩大**实际作战/集结空间**、分路或分梯队进场。不要盲目增大地图而不修正局部堆叠，也不要为了硬塞所有兵员不合理拓宽城门。512v512 是并存压力测试，不是全屏同一点。
- 验收参考 `ACCEPTANCE_MATRIX.md §7F-F`：对比同种子战线的近景/远景、极端同坐标人数、局部密度峰值、军阵宽度和纵深、狭口吞吐、击杀/存档守恒、FPS/帧时间。**少量合法重叠不判失败**。性能优先低复杂度群体逻辑，玩家不管理密度菜单。
- 直接在当前已有可玩河关候选/集成分支渐进修复，不推倒现有成果，不暂停其他 Codex 总任务等待 Owner 再发下一条。

## 最新 Owner 战争结算决定（2026-11-12）：士气 + 战斗强迫性 + 多种结束方式

**读取 `PRODUCT_DECISIONS.md §1N` 和 `docs/BATTLE_MORALE_COMBAT_COMMITMENT_AND_OUTCOMES_V1.md`。** 这是新的正式战斗规则，不能把当前单一战损阈值/目标结算误当完整系统。

- 战斗可以通过**全歼、溃败逃散、有序战略撤退、投降**等不同方式结束；原有攻城、守点、护送、救援、突围等任务完成结果仍然保留。任务成功可以发生在敌方有大量幸存者时，不得把局部目标胜利伪报为全歼。
- **士气（Morale）**影响有效战斗力、阵型、命令执行和服从/忠诚倾向。伤亡速度与比例、将领伤亡、敌强我弱、突袭、包围、退路/粮道断绝、目标丢失会影响士气；援军、整队、成功任务和继任可恢复/稳定。士气为零时队伍会尝试逃散/弃械/投降或失去组织；局部队伍先变化，不要全军同一帧同步逃跑。
- **战斗强迫性（Combat Compulsion）是第二个独立指标**：权威/合法性、首府/政权威望、军纪、使命必要性、指挥链与副将继任、退路和投降条件，决定低士气时部队是否仍会守阵、服从、继续抵抗或有序撤退。它不等于士气、不加攻击力、不让低士气军队变无敌。
- **主帅被杀不自动胜利或自动溃败**：首府/政权威望高、任命合法、有副将接任时军队可能继续作战；无继任、权威弱、军心低且被包围时才可能连锁溃散/投降。要使用当前 `officer_corps.gd` 的真实继任机制并增量接入权威，不凭空造将领。
- **溃逃后给玩家一个简单追击选择**：追击可能带来俘虏/战果，也有疲劳、队形散乱、后卫反击/伏击风险；停止追击可保全军、占领目标，敌残部可能重组。有序战略撤退与无序溃逃必须区分。
- 当前代码已存在每兵归一化士气、局部 ROUT、任务层战力/崩溃计数、军官死亡后的副将继任；但尚缺独立战斗强迫性、主帅逃跑/投降决策、完整有序撤退和溃逃追击流程。先审查现有 `battle.gd`、`field_objectives.gd`、`officer_corps.gd`，**复用并扩展，不要重写**。
- 以小队/军队聚合和事件驱动更新为主，普通兵继续轻量 AI。玩家只面对清楚的军心提示和少量战后选择，不做复杂军政微操。验收按 `ACCEPTANCE_MATRIX.md §7F-G`；真实代码/录像/存档回归前不得宣称已完成。

**优先级关系**：视觉品质纵切片仍是当前 P0（PR #31 是在研的 RC3 美术整合候选，不得因本系统设计打断/覆盖它）。在视觉资产纵切片稳定后，把士气/强迫性/结局系统作为下一项重要的战斗系统开发；如有独立文件可安全并行，不得多人抢改 `battle.gd` 等热文件。

## 最新 Owner 数据粒度决定（2026-11-12）：共享兵种属性与分队士气，禁止普通兵逐人重复数据

**读取 `PRODUCT_DECISIONS.md §1O`、`SIMULATION_CONTRACTS.md §9G`、`ACCEPTANCE_MATRIX.md §7F-H`。** Owner 明确普通士兵不应每个人独立保存攻击力、防御力和士气；同一批士兵可共享很多属性，整支军队也可共享大量数据以降低计算成本。

- **兵种/装备 profile**：同兵种、同武器/护甲/训练档共享基础攻击、防御、护甲、武器性能、移动速度、最大生命等静态数据。使用共享模板引用，不在每个 Unit 复制同一组数值。
- **军队级数据**：共享基础士气、战斗强迫性、首府/政权威望、军纪、使命、整体补给/指挥权威等。
- **分队级动态状态**：Company/Detachment 共享当前士气、凝聚力、疲劳、局部伤亡比例、接敌压力和命令。局部事件先影响本队，消息传播后再影响其他队伍。士气主要是分队状态，整军士气从分队聚合。
- **单兵只保留必要差异**：ID/所属分队和 profile 引用、位置/朝向、当前动作/轻量 FSM、必要 HP/伤势/生死/俘虏/逃散状态，以及确实不同的装备/弹药。最大 HP/基础攻击/防御/护甲从模板读取；相同批次库存可以共享。
- **禁止**每个普通兵随机独立 morale、每次受击逐人扣 morale、把同批相同攻防复制为 1024/10000 份，或每帧重复计算相同静态属性。普通兵仍能逐人受击/倒地/死亡；远景可批次模拟，人员/装备/战损/存档必须守恒。重要将领和主角可保留个体状态。
- 当前 `battle.gd` 的 `Unit.morale` 是逐兵随机初始化、逐击扣减；护甲也在 Unit 中重复保存。Codex 应在视觉 P0 后，增量迁移普通兵士气至 Company/分队，建立共享 CombatProfile 或同等方案，并保留单兵必要 HP 与旧档兼容。**先 profiling，不强制 ECS，不要推倒 RC2/RC3。**

## 一、最终交付：真正值得反复玩的 macOS 战斗首版

从**现有 Godot 4 项目和已制作的河关可玩候选**继续开发，不重新建仓库、不将历史可选内容当必做表格。以 Owner 真正关心的体验为验收核心：

2. **按战役实际兵力与战场范围动态存在的军队**，标准压力样本为 512 对 512 名普通兵（同时保有 1024 个真实兵员身份，不含主角及额外军官/坐骑），各有持续身份、武器、必要的单兵生命/伤势与真实伤亡；相同兵种共享攻击/防御 profile，同一分队共享士气，视野内持续挥砍/格挡/射箭/溃逃，视野外仍有可信因果结算，回到原位置不能凭空复活或全体暂停。**普通兵可以低成本 FSM 和小队共享行动，性能优先。**
3. **九种可实际操作的武器**：剑、刀、棍、枪、长刀、弓、弩、剑盾、双剑。每种有相匹配的持握、动作、攻击范围、起手/后摇、Q/E/其他技能、命中与防守/反制，不能仅更换名称、图标或攻击数值。早期主角仍弱且可被杀，成长后在适当局面可累计杀数十普通兵，不把生命值膨胀成无敌。
4. **双方强将同样具有战斗力**：玩家不是独享英雄机制。敌我先锋、叫阵小将/精锐、分队将领、战场主将有独立武器战斗与统军行为；全军主帅可以留在后方、不在地图中。重要将领之间的战斗依靠可见动作、站位、时机、格挡/闪避、技能和反制；敌将会主动杀伤己方士兵/将领而非等玩家找他。受伤/被救、亲卫保护、撤离/被俘/阵亡、指挥继任有可信后果。**斩将不直接胜利。**
5. **真正的军事胜负**：各方战略目的、守点/攻门/护送/突围/救援、地形、战线、有效兵力、阵型、指挥链、预备队、士气、补给与撤退通路共同决定结果。固定“死亡达到 72% 即全局判定”只能作为局部士气/战力因素，不能一刀切。玩家战死结束该人生，但不能因此把存活友军从世界中删除或自动宣告对方取得整个战争的战略胜利。
6. **一张高品质战场优先，但不锁死面积和人数**：继续打磨河关地图/城门/道路/桥/坡/树林、战线、城门攻守、多个局部目标和真实物流干预，修正队伍拥挤、避碰/阵型、门楼遮挡、镜头/操作和关键战况可读性。**历史上的夜战、山林、火攻、海战、火炮等仅为灵感库**，仅选实际能明显提高乐趣又不显著增加复杂度的项目，其他允许不做。不要铺开二十张粗糙地图或让玩家管理大量粮袋/水井/弹药菜单。
7. **美术、动作、声音、UI 真实提升**：近景能看清脸、手、服装、甲胄与真正持握武器；远景能认出兵种、军旗、阵型与交战动作。优先角色姿态/武器打击、受击/倒地/骑乘、场景光影/材质、真正有辨识度的战争声音；不用生成概念效果图冒充实际 Godot 画面。UI 少、清晰、符合军事任务的实时操作，不堆满浮窗。

- 近景声音辨识度待真人试听；成长主角/敌将一战击败数十普通兵尚缺连续实录；首次 macOS 兼容后端停步根因待定位。

### 阶段 B0：视觉品质重建（当前 P0，优先于新增功能和零碎性能微调）

**Owner 明确指出：当前候选的实际画面仍然粗糙，视觉品质是下一阶段首要问题。** 完整执行标准见 [`docs/VISUAL_QUALITY_TARGET_V1.md`](VISUAL_QUALITY_TARGET_V1.md)。先解决视觉基础，再把同一标准扩展到全军，而不是先做更多系统或只调整几个遮挡参数。

当前代码审计发现：
- `scripts/field/figures.gd` 用 `mesh_builder.gd` 的 rod/block/loft 等基础程序几何构成人物；
- `scripts/field/figure.gdshader` 用顶点弯曲实现大量动作；
- `scripts/field/landscape.gd` 以程序化几何生成地面、河流、城门、营寨、植被和冲车；
- 正式游戏资源树目前基本只有字体资源，缺少成体系的真实角色模型、材质贴图、骨骼和可复用动画资产。
所以粗糙感是资产与美术基础问题，不能只靠加阴影、改颜色、提高多边形数或增加粒子解决。

**先做直接进入正式游戏的视觉纵切片**：主角完整模型 + 普通步兵 + 弓弩手 + 一名精锐/叫阵小将 + 一匹马 + 至少三类武器真实持握/动作 + 一段正式河关地形/城门/植被 + 同屏近/中/远三档士兵。采用可信比例、服装层次、真实材质和正常玩家镜头，输出真实 Godot 连续战斗录像和多距离实帧。可以自主使用 Blender/GLTF/骨骼/材质流水线或更优方案，所有资产须原创或有合法可再分发许可，不新增未经授权费用。

**视觉风格**：克制写实的小模型、真实材质与可信的古代军民服饰；人物不放大成 AAA 角色，不做塑料玩具/卡通或奇幻重甲。普通人衣物朴素、麻布粗布、皮革和有限护具；精锐/将领靠剪裁、装备、姿态和旗号区别，不靠浮夸装饰。正常战斗镜头能辨认脸、手、服装、甲胄、兵器轮廓和实际握持。

**先把少量关键角色与一段场景做精致，再将资产与 LOD 标准扩展到全部兵种和战场**。近景人物高质量，中景可辨兵种与武器，远景保持真实动作/阵型与低成本 MultiMesh；不能为画质让 1024 人性能崩溃，也不能为了性能让近景仍然粗糙。优先复用批量渲染架构，采用模型/材质合批、LOD、动画降频和可见性管理。

**验收标准**：正常游戏镜头、正常缩放和真实连续战斗录像；近景角色、武器握持、布/皮/金属/木/石材质、环境构造和动作质量显著提升。必须对比旧版同一镜头、同一画质、同一兵力，证明是游戏内实际资产升级，不是静态渲染图。纵切片达到标准后自主扩展，不需要 Owner 对普通美术细节逐项批准，也不能停下来等待下一条指令。

本阶段先于原阶段 B 的零碎近战遮挡修补和其他非阻塞优化。**可以同时修复会阻止美术工作的关键 bug，但不应让性能微调/新功能继续占用主要开发精力。** 性能 profiling 和 M5 目标仍保留，最终对升级后的真实资产重新测量。
